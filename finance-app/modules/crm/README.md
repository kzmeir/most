# Поток C — Коммерция (`modules/crm`)

Стартует после первых экранов `modules/pm`. КП (генератор) и договоры пока живут в ядре (`db.proposals`, `db.contracts`) — их читаем, новые сущности — в коллекциях модуля.

Ставки и форматы КП: память директора — ЭП 900 ₸/м² без НДС (BI бизнес), РП ЖК 5 300 ₸/м² без НДС, виллы 25–30 тыс. ₸/м² с НДС, оплата 30/30/30/10; шаблон КП — docx-генератор на `Y:` (см. историю КП в `C:\Users\Admin\Documents\Коммерческие`).

## Коллекции
`crmLeads` (источник, заказчик, объект, площадь, стадия ЭП/РП/АН, ответственный, статус: новый → расчёт → КП отправлено → торг → договор / отказ с причиной, связь с `proposals.id` и `contracts.id`), `crmPayments` (график по договору: этап, доля %, сумма, срок, привязка к этапу pm `pmProjectId + stage`, статус: ожидается / выставлен акт / оплачен), `crmTemplates` (шаблоны документов: договор, ДС, АВР, счёт — текст с полями `{{заказчик}}`, `{{сумма}}`…).

## Задачи
1. Воронка лидов: канбан по статусам и таблица, конверсия КП → договор, причины отказов, средняя ставка ₸/м² по типам объектов.
2. График платежей по договору (шаблон 30/30/30/10), привязка этапов оплаты к этапам проекта; при отметке этапа в pm (`pm.item.done`) — подсказка «пора выставлять акт» (запрос бухгалтеру в `db.docs` — через CORE-REQUESTS, если нужен новый API ядра).
3. Шаблоны документов: заполнение по данным договора и проекта, выгрузка HTML для печати/PDF (как генератор КП в ядре).
4. «Договор подписан» → `ctx.modules.pm.createProject(ctx, { track, name, client, projectId, start, due }, userId)` и событие `crm.contract.signed`.
5. Отдать финансам ожидаемые поступления: функция `expectedPayments(ctx, from, to)` для прогноза денег (подключит ядро).

Права: руководители — всё; секретарь — лиды и документы; ПМ — лиды своих объектов (чтение); остальные — нет.
