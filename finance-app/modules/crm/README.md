# Поток C — Коммерция (`modules/crm`)

Стартует после первых экранов `modules/pm`. КП (генератор) и договоры пока живут в ядре (`db.proposals`, `db.contracts`) — их читаем, новые сущности — в коллекциях модуля.

Ставки и форматы КП: память директора — ЭП 900 ₸/м² без НДС (BI бизнес), РП ЖК 5 300 ₸/м² без НДС, виллы 25–30 тыс. ₸/м² с НДС, оплата 30/30/30/10; шаблон КП — docx-генератор на `Y:` (см. историю КП в `C:\Users\Admin\Documents\Коммерческие`).

## Коллекции
`crmLeads` (источник, заказчик, объект, площадь, стадия ЭП/РП/АН, ответственный, статус: новый → расчёт → КП отправлено → торг → договор / отказ с причиной, связь с `proposals.id` и `contracts.id`), `crmPayments` (график по договору: этап, доля %, сумма, срок, привязка к этапу pm `pmProjectId + stage`, статус: ожидается / выставлен акт / оплачен), `crmTemplates` (шаблоны документов: договор, ДС, АВР, счёт — текст с полями `{{заказчик}}`, `{{сумма}}`…).

## Задачи
1. Воронка лидов: канбан по статусам и таблица, конверсия КП → договор, причины отказов, средняя ставка ₸/м² по типам объектов.
2. График платежей по договору (шаблон 30/30/30/10), привязка этапов оплаты к этапам проекта; при отметке этапа в pm (`pm.item.done`) — подсказка «пора выставлять акт» (запрос бухгалтеру в `db.docs` — через CORE-REQUESTS, если нужен новый API ядра).
3. Шаблоны документов: заполнение по данным договора и проекта, выгрузка HTML для печати/PDF (как генератор КП в ядре).
4. «Договор подписан» → `ctx.modules.pm.createProject(ctx, { track, name, client, projectId, start, due }, userId)` и событие `crm.contract.signed`.
5. Отдать финансам ожидаемые поступления: функция `expectedPayments(ctx, from, to)` для прогноза денег (подключит ядро).

Права: руководители — всё; секретарь — лиды и документы; ПМ — лиды своих объектов (чтение); остальные — нет.

## Сделано (24.09.2026)

Файлы: `domain.js` (чистая логика, `window.MostCRM`), `server.js` (`/api/crm/*`), `ui.js` (экраны + help), `tests/api_test.sh`, `CORE-REQUESTS.md`.

- **Лиды и воронка** (`crmleads`): канбан по статусам и таблица, фильтры (статус, тип, мои, поиск), KPI; аналитика — воронка по статусам, конверсия КП → договор (отказы до КП не считаются) и по всем закрытым, причины отказов, средняя ставка ₸/м² **без НДС** по типам объектов (взвешенно по площади; отдельно КП и договоры; НДС из `settings.vatRate`). Отказ — только с причиной; история статусов в лиде. «Из реестра КП» — лиды по `db.proposals`, ещё не связанным (статус КП переносится).
- **Карточка лида** (`#/crmlead?id=`): реквизиты, КП, договор, проект, история, кнопки статусов. **«Договор подписан»** (руководитель): №/дата/компания/сумма, связь с договором реестра (`db.contracts`, № и дата вытаскиваются из названия), затем `ctx.modules.pm.createProject(...)` (или привязка существующего проекта pm, или без проекта), график платежей по шаблону стадии, событие `crm.contract.signed { contract, pmProjectId }`.
- **График платежей** (`crmpay`, руководители): шаблоны 30/30/30/10 по стадиям (РП: аванс / этап 4 «Финальные планы» / этап 7 «Комплектация» / этап 9 «Выдача»; ЭП: аванс / 5 «Планы» / 7 «Рендеры и согласование ЭП» / 8 «Градсовет»; АН; концепция — первый этап ЭП), редактор строк с привязкой к этапам проекта, статусы Ожидается → Акт выставлен → Оплачен. Ожидаемая дата: вручную → акт + срок → подписание + срок (аванс) → окончание этапа pm (план/факт) + `settings.paymentTermDays`. «Пора выставлять акт» — все пункты этапа сделаны (считается на лету; обработчик `pm.item.done` ставит `readyAt`). Ожидаемые поступления по месяцам на 6 мес. «+ По договору из реестра» — график по старому договору на остаток.
- **`expectedPayments(ctx, from, to, opts)`** — экспорт модуля для прогноза денег (подключение — `CORE-REQUESTS.md`, п. 1).
- **Документы** (`crmdocs`, руководители и секретарь): шаблоны с полями `{{заказчик}}`, `{{сумма_прописью}}`, `{{график}}`… (список полей — в форме шаблона). Договор и ДС — HTML для печати/PDF; АВР и счёт — **данные для бухгалтера** по этапу оплаты + CSV (`;`, UTF-8 BOM) для 1С — официальные документы выписываются в 1С. Встроенные шаблоны можно менять и сбрасывать, можно добавлять свои. Значения экранируются.
- **Счётчики** (`ui.setBadge`): лиды с наступившим «следующим контактом» (или новые без контакта > 3 дней); платежи «пора выставлять акт» + просроченные (только руководителям).
- **Права на сервере**: руководители — всё; секретарь — лиды (чтение/запись, без удаления и подписания) и документы; ПМ — только чтение лидов, где он ответственный или ПМ/ГИП связанного проекта; бухгалтер, ГИП, руководитель раздела, сотрудник — 403. КП и договоры ядра отдаются только через `/api/crm/meta` (на сайте ERP `/api/proposals` — 404).

```
cd finance-app

set DATA_DIR=data-dev\crm& set DEV_USER=owner& set DEV_SPLIT=1& set PORT=3103& set ERP_PORT=3113& node server.js   # два сайта
```
Роль — cookie `devrole=secretary` / `pm` / `accountant`. Путь: «Из реестра КП» → карточка лида → «Договор подписан» → проект в «Проектах» → отметить пункты этапа «Финальные планы» (РП) или «Планы» (ЭП) → в «Графике платежей» «пора выставлять акт» → «Документы» → «Данные для АВР» → CSV.
