# Поток H — Аналитика (`modules/analytics`)

Блок «Аналитика» из исходного плана ERP (решение директора 24.09.2026). Панель директора: одна страница, где видно состояние бюро — деньги, проекты, люди, продажи. Только чтение, ничего не вводит.

## Где
Сайт «Финансы» (`site: 'fin'`, поддержка есть в ядре erp/main), видят только owner и partner. Остальные — 403.

## Что показать (по данным, которые уже есть)
1. **Деньги** (ядро `lib/domain.js`: `receivables`, `cashForecast`, налоговый календарь, операции `db.ops`): остаток на счетах по компаниям, дебиторка и просрочка, прогноз денег на 3 месяца (с ожидаемыми поступлениями `ctx.modules.crm.expectedPayments`), выручка/расходы по месяцам за 12 мес., маржа по проектам (контракт без НДС − субподряд − ФОТ-оценка).
2. **Проекты** (`ctx.modules.pm`): портфель ЭП/РП по статусам, просроченные и «горящие», буферы Метода Пульса (зелёный/жёлтый/красный), блокеры > 14 дней, загрузка ГИП/ПМ.
3. **Продажи** (`ctx.modules.crm`): воронка, КП в работе, конверсия, средняя ставка ₸/м² по типам.
4. **Люди** (`ctx.modules.hr`, если модуль включён — иначе блок скрыт): часы по проектам и разделам, загрузка против ёмкости, себестоимость часа (`laborCost`).
5. **Сигналы** сверху страницы: 5–7 главных проблем недели (просроченная дебиторка > 30 дн., проект в красной зоне, кассовый разрыв в прогнозе, раздел перегружен, КП без ответа > 14 дн.).
Каждая плитка — ссылка вглубь (в финансы, в карточку проекта на ERP — порт из настроек как в crm `/api/crm/meta`, в воронку).

## Правила
- Только чтение: никаких записей в чужие коллекции. Собирай данные через функции модулей (`ctx.modules.<id>`) и `lib/domain.js`; если нужной функции нет — не лезь в чужой код, опиши в `CORE-REQUESTS.md` (для ядра) или напиши координатору (для модулей).
- Графики — чистый SVG/CSS без библиотек (или Chart.js с cdnjs), тёмная и светлая тема как у остального приложения, телефон — плитки в одну колонку.
- Зона: только `finance-app/modules/analytics/`. Рабочий сервер (3000/3001, `\\MostServer\Documents\MOST-Финансы`, задачи «MOST Финансы…») не трогать. Тестовый порт 3108 (ERP в DEV_SPLIT — 3118). Node — только свой PID. Реальные данные не коммитить (`data-dev/`).
- Тестовая база: копия бэкапа в `data-dev/analytics/db.sqlite` (можно взять `\\MostServer\Documents\MOST-Финансы\data\backups\db-before-restart-2026-09-24_1430.sqlite`) + импорт реестра pm из `C:\Users\Admin\Documents\most-pm\finance-app\data-dev\pm\pm-import.json`.
- Тесты `modules/analytics/tests/api_test.sh`: права (все роли), сайт (на ERP — 404), корректность сумм на маленьком наборе данных, работа без hr/crm.
- Коммиты в `erp/analytics`, не пушить, не сливать; по готовности — сообщение координатору.

## Сделано (25.09.2026)

Файлы: `domain.js` (права, пороги, сигналы недели, `window.MostAnalytics`), `server.js` (`GET /api/analytics/overview`, функция `overview(ctx, opts)`), `ui.js` (панель, SVG-графики, help), `tests/api_test.sh`, `tests/overview_test.js`. Коллекций нет — модуль ничего не хранит и не пишет.

- **Сигналы недели** (до 7, сначала критичные): кассовый разрыв в прогнозе, дебиторка старше 30 дней (топ должников), проекты в красной/чёрной зоне буфера Пульса, прошедший срок по договору, блокеры > 14 дней, перегруженный раздел (план ≥ 110 % ёмкости), КП без ответа > 14 дней (без назначенного следующего контакта), налоги на ближайшие 30 дней. Каждый — ссылка в раздел.
- **Деньги** (`lib/domain.js`): остатки по компаниям — `accountBalances` (опорный остаток + операции после; счета без опорного остатка не суммируются, их число показано); дебиторка — `receivables` (возраст, должники > 30 дней); прогноз на 13 недель — `cashForecast` от известного остатка + `crm.expectedPayments` (`opts.expected`, как в ядре); выручка/расходы по месяцам за 12 мес. из `db.ops` без переводов (`catKind === 'transfer'`); налоги — `taxCalendar`; маржа проектов: `projects.contractNoVat` − субподряд (`subcontracts.project` = id или название) − ФОТ по табелям `hr.laborCost` по проектам pm, связанным с финансовым проектом (`pmProjects.projectId`).
- **Проекты** (`pm.domain`): портфель по стадиям и статусам (старые концепции — среди ЭП, `normalizeTrack`), зона и съеденный буфер — `health` (Метод Пульса), график «выполнено / съедено буфера» с диагональными зонами, горящие (срок прошёл / ≤ 14 дней / прогноз позже срока / красная зона / просрочки), блокеры > 14 дней (`blockerAge`), загрузка ГИП/ПМ по активным проектам.
- **Продажи** (`crm.domain.funnel`, если включена «Коммерция»): воронка, КП в работе, конверсия (всё время и с начала года), ставка ₸/м² без НДС по типам, КП без ответа.
- **Люди** (если включён «Персонал»): план загрузки разделов на 6 недель против ёмкости команд — `hr.domain.planLoad` (как «Загрузка» в hr); факт часов за 12 недель по разделам и проектам и себестоимость часа — `hr.laborCost`.
- Модуль «включён» = есть в `ctx.modules` и в `settings.enabledModules` (в DEV — все); выключенный блок скрыт. Ошибка одного блока не роняет панель (`errors`).
- Права: owner, partner; остальные — 403. Сайт «Финансы» (`site: 'fin'`): на ERP — 404. Ссылки на карточки проектов, блокеры, загрузку hr — на сайт ERP (порт из `erpPort`, новая вкладка), на финансы и воронку — внутри сайта.
- Графики — чистый SVG на переменных темы (светлая/тёмная), подсказки по наведению; плитки на телефоне — в одну колонку.

### Обновление 25.09.2026: субподряд и маржа
- `subcontracts.project` — свободный текст старой таблицы; привязан, только если совпал с `projects.id` или `projects.name` (как в ядре). Без привязанного субподряда маржа проекта **не считается**: в таблице «не привязан», вместо маржи — серая оценка «≤ договор − ФОТ», процент — прочерк. Над таблицей — сколько договоров субподряда не привязано (шт., сумма, разных названий).
- `GET /api/analytics/sub-links` (owner/partner, сайт «Финансы») — предложения привязки для интерфейса в ядре: `{ summary: { n, sum, paid, names, total }, levels: { high, medium, low, none }, items: [{ project (текст), n, sum, paid, subcontractIds, contractors, best, candidates: [{ id, name, status, contractNoVat, score 0..1, level high|medium|low, why, by: name|id }] }] }`, по убыванию суммы. Экспорт для ядра: `modules.analytics.subLinkSuggestions(db)`.
- `twins[]` в том же ответе — «привязан к архиву, есть активный двойник с договором»: `{ archivedProject { id, name, contractNoVat }, activeCandidate, candidates (только активные с договором, уровень ≥ medium), n, sum, paid, subcontractIds, why, level }`, по убыванию суммы; сравниваются название и id архивного проекта и тексты его субподрядов; `twinsSummary { n, sum, projects }`. На копии базы — 2 двойника (Алмеу РП → Almeu, 17 договоров, 65 млн; Hayat Meliora → Хаят Мелиора ЭП, 9 млн): у остальных архивных проектов с субподрядом нет активного проекта с суммой договора (например, у активного «Туркестан (гостиница)» договор 0).
- Сопоставление (`domain.js: tokens / matchScore / suggestProjects`): регистр и «ё», латиница → кириллица по звучанию (Dom Ministr ↔ Дом министра, Enesai Bishkek ↔ Бишкек Енесай), служебные слова (ЖК, РП, ЭП, БЦ, ТОО, очередь…) не учитываются, слова — точно / по началу (≥ 4 букв) / с опечаткой (Левенштейн ≥ 0,75), склейка без пробелов (Монте Росса ↔ Монтеросса), номера только точно (НОВА 23 ≠ НОВА 24). При равной оценке выше активные проекты с суммой договора. На копии базы: 73 из 157 договоров (270,7 млн) не привязаны, 24 названия: уверенно 12, средне 4, слабо 6, без кандидата 2.

### Обновление 25.09.2026: период, PDF, история сигналов
- **Период** `?period=month|quarter|year|12m` (по умолчанию 12 мес.; `/api/analytics/overview?period=…`): выручка и расходы (`money.period` — итог, `money.series` — ряд: для месяца по неделям, иначе по месяцам) и продажи (воронка `crm.funnel` с `from`). Остатки, дебиторка, прогноз, проекты и люди — всегда на сегодня.
- **Панель в PDF** — кнопка «⎙ Панель в PDF» → `window.print()` с правилами `@media print`: светлая тема (переменные переопределены даже при тёмной системной), A4 альбом, без меню, кнопок и переключателя периода, шапка «MOST · Панель директора — дата — период», карточки не разрываются; имя файла — дата и период.
- **История сигналов** — коллекция `analyticsSnapshots` (один документ на ISO-неделю `2026-W39`: `signals [{ key, level, title, text }]`). Снимок недели обновляется при открытии панели руководителем (запись — только если сигналы изменились), сравнивается с последней прошлой неделей: `history { week, prevWeek, diff { gone, added, kept } }` в ответе overview; `GET /api/analytics/history` — 26 последних недель. У каждого сигнала постоянный ключ (`cash-gap`, `receivables-30`, `zone:<проект>`, `contract-late`, `blockers-14`, `overload:<раздел>`, `kp-no-answer`, `tax:<дата>:<название>`); сравниваются все сигналы, не только 7 показанных. Первая неделя — подсказка «сравнение появится на следующей неделе».
