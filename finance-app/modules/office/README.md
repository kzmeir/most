# Поток I — Документы и канцелярия (`modules/office`)

Блок «Документы / админка» из исходного плана ERP (24.09.2026). Бухгалтерские документы (акты, счета, ЭСФ) — в 1С, здесь их НЕ дублируем. Здесь — документооборот бюро.

## Что сделать
1. **Входящие и исходящие письма**: № (автонумерация по компании и году: `ИСХ-MP-2026-001`), дата, компания MOST (4 компании из `settings`), корреспондент, тема, проект pm (необязательно), ответственный, срок ответа, статус (новое → в работе → ответ отправлен / закрыто), связь «ответ на №», вложения (файлы на сервере `DATA_DIR/office-files/`, как у модуля board: base64 в JSON, ≤ 20 МБ, PDF/DOCX/XLSX/JPG/PNG, проверка сигнатуры). Счётчик «ждёт ответа / просрочено».
2. **Реестр выдачи документации заказчику (накладные)**: проект pm, стадия, комплект (раздел/марка, листы, изм.), способ (бумага/эл.), кому, дата, отметка о получении; печатная форма накладной (HTML для печати/PDF, стиль MOST). История выдач по проекту — во вкладке проекта не надо, дай `ctx.modules.office.issuesOfProject(ctx, pid)`.
3. **Приказы и внутренние документы**: № приказа, дата, тип (о назначении ГИП/ПМ, об отпуске, о премии, прочее), текст по шаблону, ознакомление сотрудников (кнопка «Ознакомлен»; как подписи в kb). Персональные данные — только ФИО, без ИИН.
4. **Шаблоны**: письмо на бланке MOST (по компании), накладная, приказ — поля `{{…}}`, HTML для печати.

## Права
owner/partner — всё; secretary — письма, накладные, приказы (создаёт, правит, без удаления); ГИП/ПМ — письма и накладные своих проектов (создают/правят), остальные — свои задачи по письмам и ознакомление с приказами; accountant — чтение.

## Правила
- Сайт ERP (по умолчанию). Коллекции: `offLetters`, `offIssues`, `offOrders`, `offTemplates`.
- Зона: только `finance-app/modules/office/`. Ядро и чужие модули не трогать; проекты — через `ctx.modules.pm` (права pm для «своих проектов»). Нужна правка ядра — `CORE-REQUESTS.md`.
- Рабочий сервер (3000/3001, `\\MostServer\Documents\MOST-Финансы`, задачи «MOST Финансы…») не трогать ни для чтения, ни для записи. Тестовый порт 3109 (ERP в DEV_SPLIT — 3119). Node — только свой PID. Реальные данные не коммитить (`data-dev/`).
- Образцы бланков и писем MOST ищи только чтением (`\\MostServer\Documents`, `C:\Users\Admin\Documents\Коммерческие` — КП с печатью `stamp_project.png`); печать/подпись в шаблоны НЕ вставлять (только место «М.П.»).
- Тесты `modules/office/tests/api_test.sh` — самодостаточные (свой временный DATA_DIR с пользователями, как api_check kb).
- Коммиты в `erp/office`, не пушить, не сливать; по готовности — сообщение координатору.

## Сделано (25.09.2026, ветка `erp/office`)

Файлы: `server.js` (API `/api/office/*`, все права на сервере), `domain.js` (UMD `window.MostOffice`: права, автонумерация, статусы и сроки, шаблоны, печатные формы), `ui.js` (экраны, стили `office-*`, инструкция `help`), `tests/api_test.js` + `tests/api_test.sh`.

1. **Письма** (`offLetters`): входящие и исходящие; номер присваивается сам — `ВХ-MP-2026-001` / `ИСХ-MP-2026-001`, сквозной по виду, компании (MP, MA, MD, PD) и году; компанию и год зарегистрированного письма менять нельзя. Поля: дата, корреспондент, тема, их № и дата, проект pm, ответственный, срок ответа, текст (для бланка), заметка исполнителя. Статусы: входящее — новое → в работе → ответ отправлен / закрыто; исходящее — черновик → отправлено → закрыто. «Ответить» создаёт исходящее «в ответ на №», входящее само становится «ответ отправлен». Фильтры: ждут ответа, просрочено, мои, компания, поиск. Счётчик в меню: ждут ответа (у сотрудника — только свои).
   - **Вложения**: `DATA_DIR/office-files/<id письма>/`, base64 в JSON, до 20 МБ, PDF/DOCX/XLSX/JPG/PNG, сигнатура сверяется с расширением (подделка под PDF и EXE отклоняются).
2. **Выдача документации** (`offIssues`): накладная `НК-MP-2026-001` — проект, стадия, кому, способ (бумага / электронно / оба), комплекты строками «Марка | Наименование | Листов | Изм. | Экз.», примечание, отметка о получении (дата, кто принял). **Печатная накладная** (HTML → печать/PDF): таблица комплектов, «Передал / Принял», места М.П. Для других модулей: `ctx.modules.office.issuesOfProject(ctx, pid)`.
3. **Приказы** (`offOrders`): `ПР-MP-2026-001`, тип (назначение ГИП/ПМ, отпуск, премия, прочее), заголовок, текст — стандартный по типу, список ознакомления; сотрудник жмёт «Ознакомлен» (дата сохраняется), счётчик в меню «Приказы». Печать — на бланке со списком ознакомленных для подписей. Только Ф.И.О., без ИИН.
4. **Шаблоны и бланки** (`offTemplates`): реквизиты 4 компаний (наименование, город, адрес, контакты, БИН, руководитель) — в шапке бланков; шаблоны письма, накладной, приказа — HTML с полями `{{…}}` / `{{{…}}}`, «вернуть стандартный»; скрипты и обработчики в шаблонах запрещены. Печать и подпись в систему не загружаются — только место «М.П.». Печатная страница отдаётся с CSP (без внешних запросов).
5. **Права** (проверка на сервере): owner/partner — всё, удаление только они; secretary — письма, накладные, приказы без удаления, шаблоны только смотрит; ГИП/ПМ — письма и накладные своих проектов (по `pm.domain.isManager`), перенести письмо в чужой проект нельзя; ответственный — статус, заметка, файлы своего письма; accountant — чтение писем, накладных, приказов; сотрудник — письма, где он ответственный, и приказы, где он в списке ознакомления. «Ответить» можно только на видимое письмо.

## Как проверить

```
bash modules/office/tests/api_test.sh      (или node modules/office/tests/api_test.js)
```
Сам поднимает сервер на пустой временной базе (порт 3109, `DEV_USER=owner`) с пользователями всех ролей и двумя проектами pm, прогоняет 58 проверок (нумерация, права каждой роли, ответы, вложения и сигнатуры, просрочка, накладные и печать, приказы и ознакомление, шаблоны и реквизиты), гасит сервер, удаляет базу. Если порт 3109 занят — сразу сообщает. 25.09: 58/58, два прогона подряд.

Демо: `set DATA_DIR=data-dev\office& set DEV_USER=owner& set PORT=3109& node server.js` → http://localhost:3109 → «Документы»; роль — cookie `devrole=secretary|gip|staff|accountant`. Проверено глазами: список писем с номерами и статусами, бланк исходящего («Исх. № … на № …», М.П.), печатная накладная, приказ глазами сотрудника с кнопкой «Ознакомлен».

## Что осталось
- Реквизиты компаний (адрес, БИН, руководитель) заполнить в «Шаблонах и бланках» — сейчас на бланке только наименование и город.
- Во вкладке проекта pm показать историю выдач — функция `issuesOfProject` готова, вывод — за потоком pm.
- Регистрация писем из почты (импорт .eml) и сканирование — не делали.
- Номера не освобождаются при удалении (так и задумано); перенумерация — только вручную руководителем.
