# Модуль «Маркетинг» (mkt)

Сайт «Финансы» (`site: 'fin'`), в меню — после «Коммерции». Контент-план соцсетей, утверждение постов директором с телефона, согласия заказчиков на публикацию, итоги месяца. Правила текстов — статья kb «Голос бренда и правила постов» (`modules/kb/content/90-marketing-golos.md`).

## Сделано (27.09.2026)

- **Посты** (`mktPosts`): дата публикации, каналы (instagram, threads, telegram, linkedin), рубрика (The Lab, Архитектура как улика, Most in detail, Backstage, Diaries, Culture, Другое), заголовок, текст, картинки (порядок = слайды карусели, до 20 шт., PNG/JPG/WebP/GIF до 10 МБ), проект из `pmProjects` (необязательно), статус, комментарий директора, история (кто, когда, что), ссылка на публикацию, автор.
- **Статусы**: `draft` → `review` → `approved` → `published`; из `review` — `rework` (комментарий обязателен) или `rejected`; `approved` можно вернуть на правку; `rejected` → «В черновик». Править можно черновик, пост на правке и на утверждении; утверждённый — только через «Правка».
- **«На утверждение»** — карточки с каруселью (листается пальцем), текстом, подсказками по голосу бренда и кнопками ОК / Правка / Нет. Рассчитано на телефон 375 px.
- **Контент-план** — посты по неделям, фильтр по рубрике, статусу и периоду, предупреждение о паузе в публикациях больше недели; карточка поста — правка, загрузка и порядок картинок, «Отправить на утверждение», «Опубликовано» + ссылка.
- **Согласия заказчиков** (`mktConsents`, одна запись на проект pm): можно публиковать / нельзя (NDA) / не спрашивали, что можно (рендеры, чертежи, фото стройки), дата, заметка, кто отметил. **Правило**: пост с проектом без «можно публиковать» нельзя утвердить и отметить опубликованным — сервер отвечает 409 с понятной причиной, в интерфейсе кнопка неактивна и видна причина. Пост без проекта — можно.
- **Итоги месяца** (`mktMetrics`, запись на месяц): вручную — подписчики и охват по каналам, отклики на вакансии, заметка; автоматически — опубликованные посты по рубрикам и лиды из `crmLeads` по полю `source` (месяц создания лида по Алматы). Таблица за 12 месяцев.
- **Импорт черновиков** от ИИ — посты сразу «На утверждении», картинки в base64; всё или ничего (ошибка в одном посте — ничего не создаётся).
- **Счётчики в меню**: «На утверждение» — посты в `review` (только руководителям); «Контент-план» — на правке + утверждённые с прошедшей датой.
- Картинки лежат на диске `DATA_DIR/mkt-files/` (как у board), в базе только ключи; при удалении поста или слайда файл удаляется.
- `pmProjects` и `crmLeads` только читаются, в pm и crm ничего не пишется.

## Роли

| Роль | Доступ |
|---|---|
| owner, partner | всё: утверждение (ОК / Правка / Нет), импорт, удаление любых постов |
| secretary (помощник по маркетингу) | контент-план, картинки, «на утверждение», «опубликовано», согласия, итоги месяца; удаляет черновики, посты на правке и отклонённые |
| остальные | 403 |

## API (`/api/mkt/…`)

| Метод и путь | Что делает |
|---|---|
| `GET meta` | справочники, права, проекты pm со статусом согласия |
| `GET badges`, `GET summary` | счётчики меню; сводка: `review, rework, approved, late, week, lastPublished, pauseDays` |
| `GET review` | посты на утверждении (с историей) |
| `GET posts?status=&rubric=&from=&to=` | список; `POST posts` — новый черновик |
| `GET/PUT/DELETE posts/:id` | карточка / правка (в т. ч. `images: [ключи]` — порядок и удаление слайдов) / удаление |
| `POST posts/:id/images` `{name,type,data}` | картинка в конец карусели |
| `POST posts/:id/submit\|approve\|rework\|reject\|publish\|reopen` | смена статуса; `rework` — `{comment}` обязателен, `publish` — `{url, date}` |
| `GET files/:key` | картинка |
| `POST import` `{posts:[{date, channels, rubric, title, text, pmProjectId?, images:[{name,type,data}]}]}` | только owner/partner; до 50 постов; тело запроса до 32 МБ — большие пакеты делите |
| `GET consents`, `PUT consents/:pmProjectId` `{status: yes\|no\|unknown, what:[renders,drawings,photos], date, note}` | согласия |
| `GET metrics`, `GET/PUT metrics/:YYYY-MM` `{channels:{instagram:{followers,reach}…}, vacancyResponses, note}` | итоги месяца |

Для других модулей: `ctx.modules.mkt.summary(ctx)` — например, для панели директора.

## Что осталось

- Помощнику по маркетингу сейчас нужна роль «секретарь» (у неё есть и финансовые права). Если нужен отдельный доступ только к маркетингу — нужна новая роль или список пользователей в настройках (правка ядра).
- Отметка «можно публиковать» в карточке проекта pm (статья kb упоминает её) — сейчас только в разделе «Согласия заказчиков»; показать в pm — задача модуля pm через `ctx.modules.mkt`.
- Цифры охвата — вручную; автозагрузка из Instagram/Threads API не делалась (внешние сервисы не подключаем без согласования).
