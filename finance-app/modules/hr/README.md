# Поток B — Персонал: табель и загрузка (`modules/hr`)

Стартует после того, как в `modules/pm` появятся проекты (можно работать на тестовых через `POST /api/pm/projects`).

Исходные данные: сотрудники `db.employees` (43), ЗП `db.payroll`, ФОТ по командам — лист «ФОТ» в `G:\Мой диск\Финансы\Бюджеты проектов\MOST_Проекты РП_Бюджет.xlsx` (команды АР, ГИП, ОВ, ВК, ГП, офис; оклады ×1,45; 13-я зарплата).

## Коллекции
`hrTeams` (название, руководитель userId, раздел, сотрудники employeeId[]), `hrTimesheets` (employeeId, неделя `2026-W40`, строки: pmProjectId, раздел, часы; статус черновик/сдан/принят, кто принял).

## Задачи
1. Команды и руководители разделов; связь пользователь ↔ сотрудник (`users.employeeId`, поле уже есть в настройках пользователей).
2. Недельный табель: сотрудник вносит часы по своим проектам (из `pmProjects`, где он в команде, + «Офис/без проекта»), руководитель раздела принимает; напоминание в пятницу через `ctx.modules.sys.notify`, если модуль sys готов.
3. Стоимость часа: затраты на сотрудника в месяц (налоги — `D.payrollTaxes` из lib/domain.js) / норма часов месяца (праздники РК — `D.isHoliday`).
4. Себестоимость часов по проекту и разделу — функция `laborCost(ctx, pmProjectId)` для модулей pm и аналитики.
5. Загрузка: часы по людям и проектам на прошлые недели, план на 1–2 месяца из сроков пунктов pm (`pmItems.due`, раздел).
6. Даты приёма, премии, 13-я зарплата — в карточке сотрудника модуля (сами сотрудники остаются в `db.employees`, менять через ядро — CORE-REQUESTS).

Права: сотрудник — свой табель; руководитель раздела — табели своей команды; руководители — всё; суммы денег (ставка часа, себестоимость) — только owner/partner/accountant.
