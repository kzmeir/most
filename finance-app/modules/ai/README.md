# Поток F — ИИ-панель (`modules/ai`)

Решение директора 24.09.2026: ИИ-панель с вводом текста, на базе Claude Code (`claude -p`) под аккаунтом директора, **без ключа API**. Пилот — только руководители (owner, partner). Позже — переключение на ключ Claude API одной настройкой (`settings.ai.backend = 'cli' | 'api'`), без переделки модуля.

## Где панель
1. **Проекты** — вкладка «ИИ» в карточке проекта pm и общая панель на «Сводке». Команды: «составь план работ по новому проекту», «сделай ЗнП», «сделай ТЗ на ОВ», «протокол совещания», «письмо заказчику», «что горит по объекту», «что просрочено у ОВ».
2. **Финансы** — панель на сайте «Финансы» только для owner/partner (секретарь и бухгалтер её не видят): вопросы по деньгам и отчётам («дебиторка по Everest», «прогноз денег на октябрь», «сколько ушло субподрядчикам по Толе би») — только чтение, ответ текстом/таблицей.
   Модули сейчас подключаются только на сайте ERP — для «Финансов» нужна правка ядра: опиши в `CORE-REQUESTS.md`, что именно нужно (подключение ui.js модуля ai на сайте fin и API `/api/ai/*` там же), ядро сделает координатор.

## Правила
- ИИ **ничего не меняет сам**: черновик → кнопка «Применить» (план работ → пункты/сроки через функции pm) или «Скачать .docx».
- Контекст собирает сервер: данные проекта (стадия, пункты, сроки, договор, блокеры), регламенты из «Знаний», для финансов — нужные выборки. Персональные данные сотрудников (ИИН, оклады по фамилиям) не отправлять. Суммы договоров — только в финансовой панели.
- Вызов: `child_process.spawn` Claude Code CLI в режиме `-p` с промптом через stdin, `--output-format json`, таймаут, одна задача за раз (очередь), журнал запросов (кто, когда, команда, длительность — без ответа целиком). Если CLI не найден/не залогинен — понятная ошибка в панели, сервер не падает.
- CLI: `claude` не в PATH на этом ПК. Найди исполняемый файл Claude Code (НЕ `AnthropicClaude\claude.exe` — это десктоп-приложение), путь — настройка `settings.ai.cliPath`. Если CLI не установлен — ничего не скачивай и не ставь сам, напиши координатору, директор поставит.
- Документы (ЗнП, ТЗ) — Word по образцу MOST. Образцы ищи только чтением: `\\MostServer\Материалы для проектирования\Регламенты`, `\\MostServer\Documents`, `Y:` (концепции/ЭП). Шаблон КП MOST (docx-js) — см. `C:\Users\Admin\Documents\Коммерческие`.
- Зона: только `finance-app/modules/ai/` (+ `CORE-REQUESTS.md`). В pm не пиши — нужна вкладка в карточке pm → запрос потоку A через координатора, либо регистрируй вкладку через `window.MostUI` если pm это позволяет.
- Рабочий сервер (порты 3000/3001, `\\MostServer\Documents\MOST-Финансы`, задачи «MOST Финансы…») не трогать. Тестовый порт 3106 (ERP в DEV_SPLIT — 3116). Node-процессы — только свой PID. Реальные данные в git не коммитить (`data-dev/` в .gitignore).
- Тесты: `modules/ai/tests/api_test.sh` — права (staff/gip/secretary/accountant → 403), очередь, таймаут, backend-заглушка `settings.ai.backend='mock'` для тестов без CLI.
- Коммиты в ветку `erp/ai`, не пушить, не сливать; по готовности — сообщение координатору.

## Сделано (24.09.2026)

Файлы: `domain.js` (права, команды, разбор ответа, `window.MostAI`), `server.js` (`/api/ai/*`, очередь, бэкенды, сбор контекста), `docx.js` (Word без зависимостей), `ui.js` (панель, журнал и настройки, help), `tests/api_test.sh`, `CORE-REQUESTS.md`.

- **Подключение** (`backend`): `cli` — Claude Code `claude -p --output-format json --tools "" --strict-mcp-config --no-session-persistence --system-prompt …`, промпт через stdin, рабочая папка `%TEMP%\most-ai`, инструменты отключены (модель только отвечает текстом); `api` — Messages API через встроенный `fetch`, ключ **только** из `ANTHROPIC_API_KEY` в окружении (в базе не хранится: `/api/settings` читают все), модель `apiModel` (по умолчанию `claude-opus-5`); `mock` — заглушка для тестов. Настройки: `settings.ai` ядра ← `aiConfig` модуля (правит владелец в «Журнал и настройки»).
- **CLI найден**: `%APPDATA%\Claude\claude-code\<версия>\claude.exe` (его ставит десктоп-приложение Claude; ищется самая новая версия, путь можно задать `cliPath`). `AnthropicClaude\claude.exe` не используется. **Вход не выполнен**: отдельный запуск отвечает «OAuth session expired» — нужен `/login` директора (см. «Что осталось»). Панель показывает понятную ошибку, сервер не падает.
- **Очередь**: одна задача за раз, до `maxQueue` в ожидании (429 сверх), один ожидающий запрос на пользователя, отмена из очереди; таймаут `timeoutSec` (по умолчанию 300 с) убивает процесс. Задачи — в памяти; клиент опрашивает `/api/ai/jobs/:id` (не держит HTTP-запрос — туннель рвёт долгие). **Журнал** `aiLog`: кто, когда, команда, проект, подключение, длительность, итог/ошибка, размер промпта и ответа — без текста.
- **Команды.** Проект (ERP): план работ (сроки пунктов + недостающие пункты → «Применить»), ЗнП по форме MOST (25 строк «Шаблона ЗНП для заказчика», шапка «Утверждаю / Согласовано» в .docx), ТЗ на раздел, протокол по заметкам, письмо заказчику, «что горит», вопрос. Сводка: «что горит», просрочки раздела, план нового проекта (→ «Применить» создаёт проект в pm), вопрос. Финансы (только сайт «Финансы»): дебиторка, прогноз денег, субподрядчики по проекту, вопрос.
- **Контекст собирает сервер**: проект — поля, договор (№/дата/срок), этапы и пункты, открытые блокеры, прогресс; регламенты из «Знаний» (опубликованные, поиск `kb.domain.search`). **Бюджет проекта pm не передаётся**; финансы — дебиторка, прогноз (ЗП — одной суммой), открытые договоры, субподряд, обороты по проектам и месяцам **без операций ЗП**, операции по проекту/контрагенту, названному в вопросе. ИИН, оклады, `db.employees`, `db.payroll` не передаются (проверено на копии базы).
- **ИИ ничего не меняет сам**: ответ — черновик (`aiDrafts`, видит автор и владелец, по 60 последних на человека). «Применить» вызывает `modules.pm.handle` от имени пользователя (права проверяет pm): PUT сроков пунктов, POST новых пунктов, POST нового проекта; выбор строк галочками. «Скачать .docx» — Arial 10 pt, акцент #FF4D23, A4, поля 2 см (как КП MOST), подпись «черновик ИИ, проверен: ___».
- **Сайты**: модуль объявляет `site: ['erp', 'fin']`. Место панели — по сайту запроса: ERP — проекты, «Финансы» — только финансы (запрос финансов на ERP — 403); сайт берётся из `ctx.site`, если ядро передаст, иначе по порту (`ERP_PORT`).
- **Карточка проекта pm**: кнопка «✦ ИИ» в шапке (через `onNav`, файлы pm не менялись) → панель с выбранным проектом.
- **Права**: только owner и partner (остальные — 403); настройки и журнал — owner.

## Как проверить

```
cd finance-app
bash modules/ai/tests/api_test.sh      # 58 проверок: роли, mock, очередь, таймаут, ошибки CLI/API, .docx, «Применить», ЗнП, сайты (DEV_SPLIT)
set DATA_DIR=data-dev\ai& set DEV_USER=owner& set PORT=3106& node server.js        # копия базы с проектами pm
```
В «ИИ → Журнал и настройки» выбрать «Заглушка» — проверить интерфейс без Claude; «Claude Code» — реальный вызов (нужен вход). Кнопка «Проверить подключение» задаёт короткий вопрос.

## Что осталось

1. **Вход Claude Code под аккаунтом директора** на машине, где работает сервер: терминал под той же учётной записью Windows → `"%APPDATA%\Claude\claude-code\<версия>\claude.exe"` → `/login`. Если сервер на MostServer в **Docker** (Linux) — windows-CLI из контейнера недоступен: либо Linux-CLI Claude Code в образе с входом директора (решает поток E), либо `backend: 'api'` с ключом в переменной окружения контейнера.
2. Ядро — `CORE-REQUESTS.md`: передавать `ctx.site` в модули; включить `ai` на сайте «Финансы» (`site`).
3. Вкладка «ИИ» внутри карточки pm (сейчас — кнопка в шапке) — по желанию потока A.
4. После входа — прогнать реальные команды на 2–3 проектах, подстроить формулировки (ЗнП/ТЗ) по замечаниям директора; образцы ТЗ по разделам (сейчас структура ТЗ — типовая).
5. Потоковый вывод ответа (stream-json) — если ожидание в 1–3 минуты будет мешать.
