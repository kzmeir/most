# Поток D — Знания и обучение (`modules/kb`)

Модуль для всех сотрудников (роль `staff` и выше): новости бюро, база знаний, обучение новичков с нуля, тесты. Независим от других модулей.

Материал: `\\MostServer\Материалы для проектирования\Регламенты\` — «Список регламентов» (15 шт.: наименование файлов, ЗнП, график выдачи чертежей, чек-лист проверки РП, дорожная карта, оргструктура, матответственность, авторское право, неразглашение, регламент почты, программа стажировки, сдача СНиПов и книг, гайды по планировке и посадке с тестами), docx/pdf/xmind. Нормы — библиотека `\\MostServer\Нормативы` (не Y:\ — это теперь другой сервер) (ссылки, не копии).

## Коллекции
`kbNews` (заголовок, текст, автор, дата, закреплено), `kbReads` (кто прочитал что: `kind` = news / article / sign, дата), `kbArticles` (раздел, заголовок, текст, ссылки на файлы, теги, `source` — путь исходного файла при импорте), `kbCourses` (программа: недели → шаги → статьи/тесты/подписи, для кого), `kbTests` (вопросы: один/несколько вариантов, правильные ответы, проходной балл, попыток), `kbAttempts` (userId, testId, ответы, балл, дата), `kbEnroll` (новичок ↔ программа ↔ наставник, раздел, ручные отметки шагов).

## Задачи
1. Новости: лента, публикуют руководители и секретарь, отметка «прочитал», счётчик непрочитанных в меню.
2. База знаний: разделы (Регламенты, Гайды, Стандарты Revit ADSK, Нормы), поиск, статья с текстом и ссылками на файлы на сервере. Импорт текстов регламентов из docx (`tools/import_kb.py` в папке модуля, без npm).
3. Обучение: программа стажировки по неделям, наставник (userId), прогресс новичка в %, отметка шагов; руководитель раздела видит прогресс своих новичков.
4. Тесты: редактор вопросов (руководители), прохождение, балл, пересдача, история; событие `kb.test.passed`. Правильные ответы не отдаются в браузер до завершения попытки.
5. Документы для подписи новичком (NDA, авторское право, материальная ответственность): отметка «ознакомлен» с датой.

Права: читать — все вошедшие; писать новости/статьи — owner, partner, secretary; тесты и программы — owner, partner, lead. Модуль видят все роли (`canOpen: u => !!u`).

## Сделано (24.09.2026, ветка `erp/kb`)

Файлы: `server.js` (API `/api/kb/*`, все права — на сервере), `domain.js` (UMD `window.MostKb`: права, разбор тестов и программ, оценка, прогресс, поиск), `ui.js` (экраны, стили `kb-*`), `seed.js` (стартовое наполнение), `tools/import_kb.py` (импорт регламентов), `tools/api_check.js` (проверка API ролями), `CORE-REQUESTS.md`.

1. **Новости** — лента (закреплённые сверху), «Прочитал» с датой, счётчик непрочитанных в меню. Публикующие видят «прочитали N из M» (при наведении — кто).
2. **База знаний** — вкладки-разделы со счётчиками (Регламенты, Гайды, Стандарты Revit ADSK, Нормы, Документы для подписи), поиск по названию/тегам/тексту (ё = е). Статья: простая разметка (`#` заголовок, `-` список с вложенностью, `|` таблица, `**жирный**`); путь `\\MostServer\…` / `Y:\…` копируется щелчком (браузер не открывает file://), http-ссылки открываются. Открытие статьи = «прочитано». К статье показываются связанные тесты.
   - **Импорт** `tools/import_kb.py`: docx → текст (заголовки, списки, таблицы), XMind → вложенный список, PDF/PNG → ссылки к документу своей папки. Повторный импорт обновляет статьи по пути файла, копий не плодит. Сейчас на сервере 4 файла + папка «Дорожная карта проекта» → 7 статей.
3. **Ознакомление** — документы раздела «Документы для подписи»: «Ознакомлен» с датой; руководители и секретарь видят сводную «сотрудник × документ», руководитель раздела — только свой раздел.
4. **Тесты** — редактор в текстовом формате (`?` вопрос, `+` верный, `-` неверный; несколько `+` → несколько ответов), проходной балл, лимит попыток, статья для подготовки. Прохождение → балл, разбор (зелёные/красные варианты), пересдача, история и «Разбор» каждой попытки. Правильные ответы отдаются только после попытки. При сдаче — событие `kb.test.passed`.
5. **Обучение** — программа по неделям в текстовом формате (`# Неделя`, `- шаг | статья: … / тест: … / подпись: …`); шаги со ссылкой засчитываются автоматически (статья открыта, тест сдан, документ подписан), задания отмечают новичок или наставник. Назначение: новичок, программа, наставник, раздел, дата начала; прогресс в %, статус «завершено» сам при 100 %. Видят: новичок, наставник, owner/partner, руководитель раздела новичка.
6. **Стартовое наполнение** (кнопка у owner/partner в «Базе знаний», повторно не дублирует): статьи «Библиотека норм (Y:)», «Стандарт ADSK», «Структура папок проекта»; 3 документа для подписи (**тексты-заготовки — заменить утверждённой редакцией**); тест «Регламент РП: этапы и ответственные» (8 вопросов по реальному регламенту); программа «Стажировка архитектора (4 недели)», 16 шагов.
7. **«Ждёт вас»** (уведомлений нет — решение директора): блок на главной модуля («Новости») — документы на ознакомление, несданные тесты из моих программ, следующие 3 шага каждой программы; счётчики в меню: Новости (непрочитанные), Обучение (активные программы), Тесты (ждут сдачи), Ознакомление (не подписано). Данные — `GET /api/kb/summary` → `waiting`.
8. Для других модулей: `ctx.modules.kb.progressOf(ctx, userId)` → `[{course, status, pct}]` (например, для hr).

9. **Реальное наполнение** — `content/*.md`: 19 отредактированных статей вместо сырых текстов.
   - **Регламенты (10):** регламент РП по этапам (таблицы «что — кто — срок — результат»), дорожная карта ЭП → РП, порядок работ ЭП (ред. 06.10.2025), анализ участка и ИРД, правила наименования файлов (из PDF), согласование эскиза и частые отказы, ЗнП, ИРД со сроками, письма заказчика для экспертизы, карточка решений КЖ.
   - **Гайды (5):** шаблон альбома ЭП (набор «MOST-шаблон-ЭП»: 10 шагов сборки, ссылки на xlsx/docx/rte и учебный альбом-стандарт), состав альбома и нумерация, чеклист выпуска, структура папок, словарь сокращений и ролей.
   - **ADSK (2), Нормы (2):** спецификации В_/О_ и «почему спека пустая», именование и штамп; как найти действующую редакцию в `\\MostServer\Нормативы`, указатель ключевых норм, поквартирная инсоляция.
   - Источники: `\\MostServer\Материалы для проектирования\Регламенты`, шаблоны ЗнП и ИРД, схема папок, набор `Y:\Concept Projects EP\00-Cowork-gpt-claude\MOST-шаблон-ЭП`, каталог норм. Импортёр заменяет сырой текст файла-источника (поле `source:`), убирает дубли (`skip:`), ссылки на исходные файлы сохраняет.
   - Стартовое наполнение: 2 теста по 8 вопросов (регламент РП; альбом ЭП и рабочие файлы), программа стажировки 4 недели / 21 шаг по этим статьям.

10. **Инструкция** — поле `help` в `ui.js`: общий пункт «Что такое „Знания“» и по пункту на каждый раздел меню (новости, база, обучение, тесты, ознакомление) — шаги для сотрудника и кто что может. Кнопка «?» в шапке раздела ведёт на свой пункт.
11. «Стартовое наполнение» грузит и статьи `content/*.md` — Python для первого запуска не нужен; импорт регламентов и кнопка в любом порядке не создают дублей.

12. **Черновики** (решение директора 24.09): поле `draft` у статей и тестов (`draft: true` в шапке `content/*.md`, `draft: true` у теста в `seed.js`). Черновики видят только owner/partner/lead — сервер не отдаёт их сотрудникам ни в списках, ни по прямой ссылке, ни в «Ждёт вас»; снимают отметку owner/partner/lead кнопкой «✓ Проверено — опубликовать» (`POST /api/kb/articles|tests/:id/approve`). Повторное наполнение и импорт проверенное в черновики не возвращают.
13. **Первая волна по PROPOSALS (приоритет A)** — 8 черновиков в `content/40–47`: ЗнП без споров; комплект ИРД для госэкспертизы; протокол встречи и карточка решений; разбор отказа по ЭП (ФОК); расчёт парковок; «Общие данные» и титул перед выпуском; самопроверка альбома АР перед экспертизой (чек-лист ☐); замечания экспертизы — как отвечать. Плюс черновой тест «Экспертиза и выпуск: типовые замечания» (10 вопросов). Источники — проекты на Z:/Y: (только чтение), формулировки переработаны, персональных данных и сумм нет. В программу стажировки добавить после проверки.

## Как проверить

```
cd finance-app
python modules/kb/tools/import_kb.py "\\MostServer\Материалы для проектирования\Регламенты" data-dev\kb\kb-import.json
set DATA_DIR=data-dev\kb& set DEV_USER=owner& set PORT=3104& node server.js
node modules/kb/tools/api_check.js
```

`api_check.js` ждёт **чистую** тестовую базу с пользователями `dev-owner, dev-partner, dev-secretary, dev-gip, dev-lead (lead, АР), dev-staff (staff, АР), u-kj (staff, КЖ)` — id совпадают с входом `DEV_USER`, чтобы у dev-ролей были имена и разделы (реальную базу в тест не копировали). Результат 24.09 (после перехода ядра на SQLite, база `data-dev/kb/db.sqlite`; старый db.json переезжает сам): 36/36 проверок (публикация и права ролей, прочтение, импорт без дублей, скрытие ответов, лимит попыток, видимость новичков по разделам).

В браузере: http://localhost:3104 → «Знания». Роль — cookie `devrole=staff|lead|secretary…` (+ `devsection=АР` для руководителя раздела). Проверено глазами: новости и счётчики, база/поиск/статья, прохождение теста с разбором, карточка обучения, сводная ознакомления, редактор теста.

## Что осталось

- **Порядок на рабочем сервере:** сначала «Импорт регламентов» (файл из `import_kb.py`, он включает `content/*.md`), потом «Стартовое наполнение» — тогда тесты сразу привязаны к статьям.
- Статьи бюро правятся в `content/*.md` (шапка: section, title, tags, source, skip, links) и импортируются заново; правки из интерфейса повторный импорт перезапишет.

- **Регламенты**: в `Регламенты\` на сервере только 4 файла + «Дорожная карта»; «Список регламентов» из 15 (ЗнП, график выдачи чертежей, чек-лист РП, оргструктура, регламент почты, программа стажировки, сдача СНиПов, гайды по планировке/посадке с тестами) не найден — положить файлы и повторить импорт. «Правила наименования файлов» есть только в PDF (статья-ссылка без текста).
- **Документы для подписи**: заменить заготовки утверждёнными текстами; при желании — загрузка скана подписанного документа (нужна файловая часть в ядре/sys).
- Тесты по гайдам планировки и посадки — составить в редакторе, когда появятся гайды.
- Связь с hr: дата приёма сотрудника → автоназначение программы новичку.
- Файлы-вложения к статьям (сейчас только ссылки на сервер).
- Запросы к ядру — `CORE-REQUESTS.md` (хук для счётчиков меню, лишние 403 у сотрудника).
