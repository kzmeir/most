# Поток G — Доска (аналог Miro) (`modules/board`)

Решение директора 24.09.2026: своя доска вместо Miro, данные на своём сервере. Первая версия — к утру 25.09.

## Первая версия (задание)
- Бесконечный холст: масштаб колесом/щипком, перемещение (пробел+мышь, два пальца), мини-карта не обязательна.
- Объекты: стикер (цвета), текст, прямоугольник/рамка-раздел с заголовком, стрелка/линия между объектами (привязка к объектам), картинка, PDF-лист (первая страница или выбранные — рендер через pdf.js с cdnjs/jsdelivr или локальную копию в модуле; без npm-зависимостей на сервере).
- Выделение, перемещение, изменение размера, удаление, копирование, отмена/повтор (Ctrl+Z / Ctrl+Y), выбор рамкой, группа.
- Перетаскивание файлов (jpg/png/pdf) на доску; файлы хранятся на сервере в `DATA_DIR/board-files/<boardId>/` (лимит размера, проверка типа), в БД — только ссылки.
- Доска привязана к проекту pm (`pmProjectId`) или свободная; шаблон MOST для ЭП: рамки «ТЗ и исходные», «Участок», «Аналоги», «Концепция», «Замечания заказчика», «Решения».
- Совместная работа v1: сохранение изменений операциями (патчи по объектам с версией), опрос каждые 2–3 с, конфликт — последний выигрывает по объекту; видно «кто сейчас на доске». Курсоры в реальном времени — v2.
- Права: доски проекта — те, кто может открыть проект pm (`ctx.modules.pm` функции прав); редактировать — ПМ/ГИП проекта, руководители, участники; остальным — просмотр. Свободные доски — владелец доски + кого добавил.
- Экран «Доски» (список, поиск, «+ Доска», «+ Из шаблона ЭП»), экран доски на весь экран `#/board?id=`. Инструкция модуля (`help`).
- Хранение: коллекции `boards` (meta) и `boardItems` (объекты) — на SQLite-сторе ядра; большой объём — учти производительность (persist по diff).

## Сделано (25.09.2026, ветка erp/board)

**Коллекции.** `boards` — `{ id, title, pmProjectId ('' — свободная), ownerId, members: [userId], template, rev, createdAt/By, updatedAt/By }`. `boardItems` — `{ id, boardId, type: sticky|text|frame|rect|arrow|image|pdf, x, y, w, h, z, rot, props, rev, ver, deleted, createdAt/By, updatedAt/By }`; `props`: `text, color, size` (стикер/текст/фигура), `title, color` (рамка), `from, to, x2, y2, head, text` (стрелка: концы привязаны к объектам или к точкам), `src, name` (картинка), `src, pdf, page, pages, name` (лист PDF: `src` — PNG страницы, `pdf` — оригинал), `group`, `locked`. Удалённые объекты остаются надгробиями (`deleted: true`, `rev`), чтобы другие клиенты узнали об удалении.

**domain.js** (`window.MostBoard`, UMD): типы и значения по умолчанию, палитра, `cleanItem` (проверка всего, что приходит с клиента: типы, диапазоны, длины, ключи файлов), права `canView / canEdit / canManage / canCreateProjectBoard` через функции pm (`PM.canOpen`, `PM.isManager`, `PM.isLeader`), геометрия (`bbox`, `anchor`, `arrowEnds` — концы стрелок на границах объектов, `insideFrame`), шаблон ЭП `epTemplate` (6 рамок + подсказки + заголовок).

**server.js** (`/api/board/*`, права на сервере):
`GET|POST boards` (список видимых, создание: `title, pmProjectId, template: 'ep', members`), `GET|PUT|DELETE boards/:id` (карточка со всеми объектами и `rev`; настройки — владелец/ПМ-ГИП проекта/руководитель; удаление — с объектами и папкой файлов), `GET boards/:id/sync?since=rev&client=` (изменения после ревизии, надгробия, кто на доске, право правки), `POST boards/:id/ops { ops: [{op:'upsert', item}|{op:'delete', id}], client }` (одна ревизия на пакет, `ver+1` у объекта, последний выигрывает), `POST boards/:id/template`, `POST boards/:id/files { name, type, data: base64 }` → `DATA_DIR/board-files/<boardId>/<ключ>` (PNG/JPG/WebP/GIF/PDF, ≤ 20 МБ, проверка сигнатуры файла, ключ без пути), `GET boards/:id/files/:key` (отдача с типом и `nosniff`, кэш приватный), `DELETE boards/:id/files/:key` (только неиспользуемый), **`GET by-project/:pid`** (доски проекта + `canCreate` — для карточки pm). Присутствие — в памяти сервера (20 с), запись объектов в SQLite — одной отложенной транзакцией через 0,6 с после пакета операций (persist ядра пишет только изменённые документы), журнал операций — не чаще раза в 5 минут на пользователя и доску (создание/удаление досок и файлы — всегда). Функция для других модулей: `ctx.modules.board.boardsOfProject(ctx, pmProjectId)`.

**ui.js** — экран «Доски» (поиск, фильтр по проекту, кто на доске, ⚙ настройки, ✕), доска на весь экран `#/board?id=` и **редактор** `MostBoard.Editor(root, boardId, { full })`: DOM-объекты в мире с `translate/scale`, стрелки в SVG с маркерами, инструменты выбор/рука/стикер/текст/рамка/фигура/стрелка/файл (клавиши V H N T F R A I), колесо — масштаб к курсору, тачпад двумя пальцами — перемещение, щипок — масштаб, пробел — рука, на телефоне один палец — перемещение, два — масштаб; выделение щелчком/Shift/рамкой, перемещение (рамка тянет всё внутри, стрелки между выделенными — вместе), 8 маркеров размера (картинки пропорционально), двойной щелчок — правка текста (`textarea` в мире, текст растёт по высоте), Ctrl+Z/Y, Ctrl+C/V/D, Ctrl+A, Ctrl+G, стрелки-клавиши, Delete, Esc; панель объекта над выделением (цвет, размер, наконечник и подпись стрелки, «PDF ↗», передний/задний план, дублировать, закрепить, удалить); перетаскивание и вставка из буфера картинок и PDF (pdf.js 4.10 с cdnjs, выбор страниц «1-3,5», рендер страниц в PNG на клиенте, оригинал тоже сохраняется); операции копятся и уходят пакетом через 0,25 с, опрос каждые 2,5 с (в скрытой вкладке — реже), статус «Сохранено / Сохранение… / Не сохранено», аватары присутствующих; **`window.MostBoard.embed(el, { pmProjectId, boardId?, height? })`** — доски проекта в карточке pm (выбор доски, «+ Доска ЭП», «На весь экран»). Инструкция модуля — `help` (3 раздела).

**tests/api_test.sh** — 76 проверок: свободные и проектные доски, роли (owner, partner, accountant, secretary, gip, pm, lead, staff), настройки, операции с версиями и надгробиями, последний выигрывает, sync, присутствие, шаблон ЭП, файлы (тип, подделка сигнатуры, > 20 МБ, обход пути, удаление используемого), by-project, удаление доски с файлами, два сайта (`DEV_SPLIT=1`).

## Встраивание в карточку ЭП — хук для потока A
В `modules/pm/ui.js` рядом с вкладкой «Миро» добавить вкладку `['board', 'Доска']` (показывать, если `window.MostBoard && window.MostBoard.embed`), в отрисовке вкладки вернуть `<div id="pm-board"></div>`, а после `main.innerHTML = …` вызвать:
```js
if (tab === 'board' && window.MostBoard && window.MostBoard.embed) window.MostBoard.embed(document.getElementById('pm-board'), { pmProjectId: p.id, height: '72vh' });
```
`embed` сам показывает список досок проекта, кнопку «+ Доска ЭП» (по правам pm: ПМ/ГИП проекта и руководители) и ссылку «На весь экран»; при перерисовке карточки редактор останавливает опрос сам (проверяет, что его элемент ещё в документе). Данные — `GET /api/board/by-project/:pid`.

Что смотреть глазами: «Доски → + Из шаблона ЭП» (привязать к проекту), на доске: стикер (N + щелчок, набрать текст, Esc), перетащить, Ctrl+Z, колесо — масштаб, стрелка (A, потянуть от стикера к рамке), рамку потянуть — стикеры внутри едут с ней, перетащить PNG и PDF на холст, вторая вкладка с той же доской — изменения приходят через 2–3 с, `devrole=lead` — только просмотр. Телефон: один палец — перемещение, два — масштаб (правка на тачскрине — простое перетаскивание и панель объекта).

## Допущения и что осталось
- **Файлы через JSON** (base64 в теле, лимит ядра 32 МБ → файл ≤ 20 МБ). Для больших PDF нужен приём бинарного тела или частями — при необходимости запрос к ядру (CORE-REQUESTS пока не потребовался).
- **pdf.js с cdnjs** (не в репозитории): без интернета на клиенте PDF не разберётся — картинки при этом работают. Локальную копию можно положить в модуль, но ядро отдаёт из папки модуля только `domain.js`/`ui.js` — нужен маршрут ядра для статики модуля.
- Совместная работа — опрос 2,5 с, последний выигрывает; курсоры и выделения других участников в реальном времени, комментарии, история версий доски — v2. Локальные правки объекта, который кто-то ещё двигает, могут «отпрыгнуть» к чужой версии после сохранения.
- Свободные доски видят только владелец и участники (даже руководители) — по заданию; при необходимости расширить `canView`.
- Персистентность объектов — общий `store.save()` ядра (сравнение всех документов): при десятках тысяч объектов на всех досках стоит вынести объекты в отдельные таблицы — запрос к ядру, когда объём вырастет.
- Дальше: экспорт доски в PNG/PDF, мини-карта, выравнивание и сетка, линии-ломаные и стрелки с точками привязки, поиск по доске, шаблоны РП/концепции, вкладка «Доска» в карточке pm (хук выше — поток A), отметка «доска изменилась» в карточке проекта.
