# Поток G — Доска (аналог Miro) (`modules/board`)

Решение директора 24.09.2026: своя доска вместо Miro, данные на своём сервере. Первая версия — 25.09 (принята, erp/main 7e2bdae); вторая версия (25.09, решение директора): доступ для всех пользователей, курсоры коллег, комментарии, экспорт, мини-карта, поиск, история.

## Задание v2
1. Доступ для всех: все активные пользователи ERP видят все доски (проектные и свободные), правят их и создают новые; у доски настройка «Кто правит»: все (по умолчанию) / участники доски / только руководители проекта — меняют владелец доски, ПМ/ГИП проекта и owner/partner; удаляют доску только владелец и owner/partner; «только просмотр» — когда доска закрыта настройкой; права на сервере; пункт меню «Доска» — для всех ролей.
2. Функции: курсоры и имена коллег (присутствие раз в 1 с, координаты в памяти сервера); комментарии к объекту и к месту (ветка, ответ, «решено», счётчик нерешённых в списке досок); экспорт доски или рамки в PNG и PDF на клиенте; мини-карта; поиск текста по доске; история — кто менял последним (подсказка на объекте).
3. Тесты: права всех ролей по трём режимам, комментарии, присутствие; проверка в браузере двумя ролями.

## Сделано (25.09.2026, ветка erp/board)

**Коллекции.** `boards` — `{ id, title, pmProjectId ('' — свободная), ownerId, members: [userId], editMode: all|members|managers, template, rev, createdAt/By, updatedAt/By }`. `boardItems` — `{ id, boardId, type: sticky|text|frame|rect|arrow|image|pdf, x, y, w, h, z, rot, props, rev, ver, deleted, createdAt/By, updatedAt/By }`; `props`: `text, color, size` (стикер/текст/фигура), `title, color` (рамка), `from, to, x2, y2, head, text` (стрелка), `src, name` (картинка), `src, pdf, page, pages, name` (лист PDF), `group`, `locked`. **`boardComments`** — `{ id, boardId, itemId ('' — место), x, y, text, userId, parentId ('' — корень ветки), resolved, resolvedBy/At, createdAt, updatedAt, rev, deleted }`. Удалённые объекты и комментарии остаются надгробиями (`deleted: true`, `rev`), чтобы другие клиенты узнали об удалении. Присутствие (курсоры, выделения) — только в памяти сервера.

**Права (domain.js, проверяются на сервере).** `canView` — любой авторизованный пользователь; **руководитель доски** — её владелец, ПМ/ГИП проекта (`PM.isManager`) и owner/partner (`PM.isLeader`): правит при любом режиме, меняет настройки (`canManage`); `canEdit` по режиму: `all` — все, `members` — участники (`members`), `managers` — только руководители доски; `canDelete` — владелец доски и owner/partner; комментировать могут все, кто видит; доски создаёт любой пользователь (в том числе проектные). Модуль виден всем ролям (`canOpen: u => !!u`).

**server.js** (`/api/board/*`):
`GET boards?q&pid&mine=1` (все доски, `modes`, все проекты pm для формы), `POST boards { title, pmProjectId, template, members, editMode }`, `GET boards/:id` (объекты с `updatedByName`, комментарии с `userName`, `rev`, присутствие), `PUT boards/:id { title, members, editMode, pmProjectId }` (manage), `DELETE boards/:id` (владелец / owner / partner; удаляет объекты, комментарии, папку файлов), `GET boards/:id/sync?since&client&cx&cy&sel` (изменённые объекты и комментарии после ревизии, надгробия, `presence: [{ userId, name, client, x, y, sel, idle }]`, `canEdit`, `editMode`, `openComments`), `POST boards/:id/ops` (edit; одна ревизия на пакет, `ver+1`, последний выигрывает; удаление отвязывает стрелки, стрелка на несуществующий объект теряет ссылку), `POST boards/:id/template`, **комментарии** `POST boards/:id/comments { itemId | x,y, text, parentId }` (все), `PUT boards/:id/comments/:cid { text }` (автор) / `{ resolved }` (любой, только корень ветки), `DELETE boards/:id/comments/:cid` (автор или руководитель доски; корень удаляется с ответами), файлы `POST boards/:id/files` (edit; PNG/JPG/WebP/GIF/PDF ≤ 20 МБ, проверка сигнатуры), `GET boards/:id/files/:key` (все), `DELETE boards/:id/files/:key` (manage, только неиспользуемый), `GET by-project/:pid` (доски проекта, `project.track`, `canCreate`). Запись в SQLite — отложенной транзакцией через 0,6 с после пакета операций; журнал операций — не чаще раза в 5 минут на пользователя и доску (доски, комментарии, файлы — всегда). Для других модулей: `ctx.modules.board.boardsOfProject(ctx, pmProjectId)`, `ctx.modules.board.domain`.

**ui.js** — экран «Доски» (все доски; поиск, фильтр по проекту, «мои»; столбцы «Кто правит», объектов, нерешённых комментариев, кто на доске; ⚙ по `canManage`, ✕ по `canDelete`), доска `#/board?id=` и редактор `MostBoard.Editor(root, boardId, { full })`: всё из v1 (холст, инструменты V H N T F R A I, выделение, размер, группы, undo/redo, копирование, файлы и PDF через pdf.js, шаблон ЭП) плюс:
- **курсоры коллег**: опрос раз в секунду (в скрытой вкладке — раз в 5 с) отправляет позицию курсора и выделение; чужие курсоры со стрелкой и именем (цвет по пользователю, плавное движение), чужие выделения — цветная обводка объектов; аватары присутствующих в шапке; при смене режима «Кто правит» вкладка сама переключается между правкой и просмотром;
- **комментарии**: инструмент 💬 (C) — щелчок по объекту или месту; 💬 в панели выделенного объекта; маркеры на доске (число — сообщений в ветке, зелёный — решено), боковая панель ветки (ответы, «✓ Решено» / «↺ Открыть», ◎ показать на доске, удаление своего), кнопка 💬 в шапке — список веток с числом нерешённых и переключателем «решённые»;
- **экспорт** (⤓ в шапке, ⤓ у выделенной рамки): вся доска или рамка с содержимым в PNG (canvas: рамки с заголовками, стикеры с переносом текста, фигуры, текст, картинки и листы PDF, стрелки с наконечниками и подписями; до 4000 px по стороне) и PDF (jsPDF 2.5.1 с cdnjs, страница по размеру рисунка);
- **мини-карта** (▦ внизу справа включает/выключает, запоминается в браузере): объекты и рамка текущего вида, щелчок/протяжка переносит взгляд;
- **поиск** (поле в шапке, Ctrl+F): по тексту стикеров/фигур/текста, заголовкам рамок и именам файлов, совпадения подсвечиваются, Enter / ↑ ↓ — переход с центрированием;
- **история**: подсказка на объекте (и на стрелке) — кто и когда менял последним;
- настройки доски: название, проект, **«Кто правит»**, участники, кнопка «Удалить доску» (по `canDelete`); `MostBoard.embed(el, { pmProjectId, height })` — как в v1 («+ Доска ЭП» только для ЭП).

**tests/api_test.sh** — 102 проверки: доступ всех ролей (owner, partner, accountant, secretary, gip, pm, lead, staff) по трём режимам «Кто правит», кто меняет настройки и удаляет, операции с версиями и надгробиями, отвязка стрелок, комментарии (ветки, «решено», счётчик, права на текст и удаление, надгробия в sync), присутствие с курсорами и выделениями (сброс через `sel=-`), файлы, шаблон ЭП только для ЭП, удаление досок с файлами, два сайта (`DEV_SPLIT=1`).

## Перенос досок Miro (25.09)
- **`tools/miro_import.js`** — конвертер canvas-SVG Miro (инструмент `canvas_read_as_svg` коннектора Miro, области до 500 объектов; SVG сохраняется в файл, Miro только читается) → наши объекты: `sticky` (именованный цвет → палитра, размер текста по ширине), `textArea`/`text` → text, `g data-frame` → frame с заголовком (дети — с учётом `translate`), `rect`/`circle`/`ellipse`/`polygon` с `data-content` → rect (цвет — ближайший из палитры по RGB, размер шрифта → ближайший из наших), `line data-start/data-end` → arrow с привязкой к объектам (`data-arrow` → наконечник, `start` — концы меняются местами), `divider` → линия без наконечника, `image` → картинка, если рядом лежит файл `miro-img-<id>.png|jpg` (скачать по ссылке из `image_get_url`; размеры из заголовка файла), иначе заглушка «Картинка в Miro»; таблицы и прочие виджеты Miro → серая заглушка с подписью; рисунки от руки (`paint`) в SVG не приходят. Координаты и размеры 1:1. Режимы: `--out file.json` (для кнопки «⇪ Импорт из Miro» в списке досок, владелец/партнёр) или `--post http://… --cookie … --project <pid> --chunk 200` (сразу на сервер частями).
- **`POST /api/board/import { title, pmProjectId, sourceUrl, items, boardId?, done? }`** — только owner/partner: первая часть создаёт доску с `source: { kind: 'miro', url, at }` (в шапке доски ссылка «Источник: Miro ↗», в списке — как обычная доска), следующие части — с `boardId`; картинки едут внутри объекта (`file: { name, type, data }`) и сохраняются в папку доски; `done` чинит стрелки на отсутствующие объекты. Части до 500 объектов (лимит тела ядра 32 МБ — картинки лучше по одной-две на часть).
- **Пилот «ЭП Маяк Everest»** (https://miro.com/app/board/uXjVHKj4TjI=/, 54 виджета): перенесено 27 объектов — 2 рамки с заголовками, 3 стикера, 3 текста («Вариант 1–3»), 9 фигур с надписями (этапы слева), 6 разделителей, 1 картинка (543×1184, файл скачан); 3 таблицы Miro — заглушками; 27 рисунков от руки (paint) не перенеслись — их нет в SVG коннектора. Результат — доска на тестовой базе 3107, превью `data-dev/board/miro-mayak-import-preview.jpg`.
- **Перенос всех досок (25–26.09)** — данные лежат в `data-dev/board/miro/` (не в git): манифест `boards.json` (`{ boards: [{ slug, miro, title, project }] }` — соответствие доска → проект pm по имени), по доске папка `<slug>/` с частями canvas-SVG (`part*.svg`, `board.svg`), картинками `miro-img-<id>.<ext>` и `res.txt` (`itemId resourceId` — картинки с одним ресурсом качаются один раз и копируются). Конвертер дополнен: несколько `--svg`, `--bounds` (JSON ответа `canvas_search` с размерами), таблицы `foreignObject data-type="table"` → белый rect с текстом (JSON-delta ячеек → текст), `data-rendered-bounds` для 0×0 виджетов, `paint` пропускается, коннекторы без второго конца отбрасываются, тип картинки по сигнатуре файла (PNG/JPEG/GIF/WebP), `--project-name` → `pmProjectName` в JSON, `summary` (объекты, заглушки, картинки, байты, части). JSON больше `--max-mb` (по умолчанию 120 МБ) режется на `<slug>.partN.json` с общим `part.key` — иначе строка не влезает в V8 и в браузер.
- **`tools/miro_build.js --manifest data-dev/board/miro/boards.json [--only slug,…]`** — пакетная сборка: прогоняет конвертер по всем доскам манифеста, печатает сводку (объектов, заглушек, картинок, размер, число файлов) и пишет `summary.json`.
- **`tools/miro_upload.html` = `GET /api/board/import/page`** (owner/partner) — загрузчик для рабочего ERP: выбрать JSON (несколько сразу; части одной доски склеиваются по `part.key`, при нехватке части — ошибка), проект подбирается по `pmProjectName` через `/api/pm/projects` (точное имя, потом похожее; можно поменять в выпадающем списке), уже перенесённые доски (`source.url` совпадает) помечаются и по умолчанию пропускаются; шлёт `POST /api/board/import` частями по 200 объектов / 18 МБ, показывает прогресс и отчёт (создано, объектов, заглушек, картинок, размер, ссылка на доску).
- **`tools/miro_images.js --token-file … --board <id> --dir <dir>`** — скачивание всех картинок доски через REST v2 Miro (`/v2/boards/{id}/items?type=image` → `imageUrl?format=original`); нужен токен приложения Miro (`boards:read`), без него — по одной через `image_get_url` коннектора (ссылка живёт ~5 минут, качать сразу и параллельно).
- **Ограничения коннектора** (почему часть досок неполная): `canvas_read_as_svg` ≤ 500 виджетов в области, включая штрихи `paint` (у DC Tech 5020 штрихов из 5547 объектов); `canvas_search` не перечисляет объекты гигантских досок («matched too many items»); картинки — только по одной. Поэтому Арена 2 (13 973 объекта), Abay Joly (9453), EXPO (3511), Апорт 29 (4566), Теректы (4470), Comfort (3601) через коннектор не переносятся — нужен токен и экспорт через REST (`miro_images.js` + выгрузка объектов), DC Tech и Шымкент перенесены частично (рамки, кластеры документов и картинок).

## Материалы из папки проекта (28.09.2026)
Задача директора: «подключить доску к сетевой папке, чтобы она автоматом показывала архив, рендеры, референсы — весь визуальный материал, и чтобы они были связаны».

**Корни** (разрешённые сетевые папки, `materials.js`): настройка модуля `boardConfig['roots']` (меняют owner/partner — список досок → «📁 Сетевые папки», `GET/PUT /api/board/roots`, `{reset:true}` — сброс) → env `BOARD_ROOTS="y|Y:|\\SynologyMost\MOST-2025|ep,concept;z|Z:|\\MostServer\Projects|rp"` (id | буква | путь | стадии) → по умолчанию Y: = `\\SynologyMost\MOST-2025`, Z: = `\\MostServer\Projects` (UNC — сервер может работать без подключённых дисков; в Docker — путь тома). Путь пользователя (`Y:\…`, `\\SynologyMost\…`) приводится к `{ root, rel }`; `..`, `:` внутри пути, управляющие символы — отказ; `path.resolve` + проверка, что остались в корне; при привязке — `realpath` (ссылка/junction наружу — отказ). На дисках сервер только читает.

**Привязка** — `bd.folder = { root, rel, setAt, setBy }`: `PUT boards/:id/folder { path } | { root, rel }` (руководитель доски: владелец, ПМ/ГИП, owner/partner; сразу сканирует), `DELETE` — отвязать. `GET boards/:id/folder/candidates?q=` (кто правит) — подбор папки: индекс каталогов корней (обход в ширину до 4-го уровня, номерные папки `NNN-ГГГГ-…` не раскрываются, ≤80 чтений, кэш 10 мин) и оценка по номеру проекта (`p.no`) и словам названия (в латинице, редкие слова весят больше: «Эверест Парк» → «Everest park»); для досок проекта панель сама показывает кандидатов, руководитель подтверждает.

**Скан** (`boardMaterials`, документ на доску): в ширину, лимиты — глубина 6, 1500 файлов, 1500 папок, 20 с; только jpg/jpeg/png/webp/pdf; без `textures`, `maps`, `backup`, `AutoSave`, `Thumbs.db`, `#recycle`, `@eaDir`, скрытых, `~$` и пустых файлов. Категория (domain `matCategory`) — по папкам сверху вниз, потом по имени файла: Рендеры (render/рендер/визуал), Референсы (reference/аналог), Презентации / PDF (презентац/градсовет/альбом/`PDF`; PDF без подсказок), ИРД / Документы (ИРД/задание/АПЗ/ТУ/топо), Прочее. «Новое» — файл появился после первого скана (≤14 дней), «изм.» — изменились размер/время. `GET boards/:id/materials?auto=1` пересканирует, если скан старше 5 минут (только у тех, кто правит), `POST materials/scan` — «Обновить», не чаще раза в 15 с (`BOARD_RESCAN_MS`). Фоновых процессов нет.

**Миниатюры и копии** — на сервере нечем декодировать картинки (Node без npm), поэтому их делает браузер: `GET materials/raw/:f` отдаёт оригинал потоком с `Range` (pdf.js читает только нужные куски большой презентации), миниатюра 400 px JPEG (canvas / `createImageBitmap`; PDF — 1-я страница pdf.js с `intent:'print'`, рисует и в фоновой вкладке) уходит `POST materials/thumb` и кэшируется в `DATA_DIR/board-thumbs/<sha1(корень:путь|размер|mtime)>.jpg` (≤400 КБ, только JPEG; при изменении файла ключ другой, старая удаляется при скане); делаются только для видимых плиток, по две, с тайм-аутом. Тип «PDF» проверяется по первым байтам (в папках встречаются PNG с расширением .pdf). Копия на доску: картинка ≤3 МБ и ≤2560 px — `POST materials/copy` (сервер копирует сам, тип по сигнатуре), больше — браузер уменьшает до 2400 px JPEG и грузит как обычный файл доски; PDF — лист 1600 px (JPEG) + оригинал ≤20 МБ копией («PDF ↗»).

**Связь** — `props.srcRoot`, `props.srcPath` (путь от корня), `srcSize`, `srcMtime` у image/pdf (domain `cleanItem`, `..` не пропускается). `GET materials` возвращает `linked: { itemId: { state: ok|changed|missing, display, unc } }` (по скану; вне папки — stat, до 300). На объекте — 🔗 / «⟳ обновлён в папке» / «нет в папке»; в панели объекта 📁 (путь `Y:\…` и `\\Synology…` с «Копировать» — браузеры не открывают file://) и ⟳ «Обновить на доске» (новая копия, позиция и ширина сохраняются, отменяется Ctrl+Z).

**«Разложить всё»** — `POST materials/layout { cats? }` (кто правит) возвращает план (domain `layoutPlan`): рамки-категории `frame.props.matCat` (новые — ниже содержимого доски слева направо, существующие дополняются в свободные ячейки и растут вниз), ячейки 400×300 с подписью-именем файла; файлы, уже лежащие на доске (по `srcRoot:srcPath`), пропускаются; до 150 за запуск (остаток — следующим). Браузер выполняет план операциями (одна отмена на всю раскладку). Если в панели выбрана категория — раскладывается только она.

**Права**: просмотр материалов, оригиналов и миниатюр — все, кто видит доску; скан, «Разложить всё», копии — кто правит доску; привязка папки — руководитель доски; корни — owner/partner.

## Допущения и что осталось
- Присутствие раз в секунду — примерно 1 запрос/с на открытую вкладку (в скрытой — раз в 5 с); для офиса нормально, при десятках вкладок стоит перейти на SSE/WebSocket (нужен маршрут ядра).
- Файлы через JSON (base64, ≤ 20 МБ — лимит тела ядра 32 МБ); pdf.js и jsPDF грузятся с cdnjs (без интернета у клиента PDF-функции недоступны, остальное работает). Локальные копии библиотек потребуют маршрута ядра для статики модуля.
- Экспорт рисует объекты заново (не снимок экрана): шрифт системный, поворот объектов не учитывается, огромные доски масштабируются до 4000 px по стороне.
- Совместная правка — «последний выигрывает» по объекту; курсоры без предсказания движения (шаг опроса 1 с, анимация 0,4 с).
- «Материалы»: миниатюры делает браузер того, кто первым открыл панель (оригинал качается целиком — рендер 10–50 МБ по сети офиса быстро, через туннель медленно); PDF больше 20 МБ на доску кладётся листом без копии оригинала; скан — снимок по запросу, без слежения за папкой; на Docker-сервере корни нужно подключить томами и прописать `BOARD_ROOTS` или «Сетевые папки».
- Дальше: уведомление «вас упомянули» в комментариях, история версий доски и откат, выравнивание и сетка, ломаные стрелки, шаблоны РП/концепции, SSE вместо опроса.
