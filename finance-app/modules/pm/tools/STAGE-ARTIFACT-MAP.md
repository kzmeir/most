# Карта «этап РП → артефакт на диске»

Основа — 81-пунктный роадмап РП (`modules/pm/domain.js`, `TEMPLATES.rp`, 9 этапов) и стандарт папки проекта `Z:\№-год-название\<разделы>` (`FOLDER_SECTIONS`). Сканер (`status_scan.js`) сопоставляет наличие артефактов по разделам с этапами и выводит реальный этап консервативно (достигнут, если есть значимые файлы опорных разделов).

## Важно: нумерация папок на диске «плавает»
Стандарт в коде — `02-AR, 03-GP, 04-KJ, 05-OV, 06-VK, 07-EL, 08-SS, 09-APT, 10-POS, 11-OVOS, 12-SMETA, 13-TH`, но на реальных проектах встречается `01-AR, 02-GP, 03-KJ, 04-OV, 05-VK, 06-EL, 07-SS, 08-APT APS, 09-POS, 10-OVOS, 11-Smeta, 12-TH, 13-ГСВ` и др. Поэтому раздел определяется **по токену-дисциплине** в имени папки (AR/АР, KJ/КЖ, OV/ОВ, VK/ВК, EL/ЭЛ/ЭОМ, SS/СС/АПС, GP/ГП, POS/ПОС, OVOS/ОВОС, Smeta/Смета, TH/ТХ, GSV/ГСВ, ИРД, Задания), а не по числовому префиксу.

## Соответствие этапов и разделов

| Этап РП (роадмап) | Опорные артефакты (раздел → что лежит) | Признак достижения |
|---|---|---|
| 1. ИРД (ТУ, геология, топосъёмка, СТУ) | `ИРД`, `Задания` — АПЗ, ТУ, геология, топосъёмка | есть файлы в `ИРД` |
| 2. ГПР / График чертежей | задания, график (в `Задания`) | по диску ненадёжно — берётся из ERP/оплат |
| 3. Этап 1. Схема КЖ | `КЖ` (КЖ1 расчёт схемы), `АР` (АР1 задание смежникам), `ГП` (ГП1 рельеф) | есть файлы `КЖ` **и** `АР` |
| 4. Этап 2. Финальные планы | `ОВ` (ОВ1), `ВК` (ВК1), `ЭЛ` (ЭЛ1), `СС` (СС1), `АР` (АР2 модель), `КЖ` (КЖ2 котлован/фундамент) | есть файлы `ОВ` **и** `ВК` |
| 5. Этап 3. Проект | `ЭЛ` (ЭЛ2 схемы), `СС` (СС2), `КЖ` (КЖ3 армирование), `АР` (АР3 комплект), `ВК`/`ОВ` (аксонометрия) | есть файлы `ЭЛ` **и** `СС` |
| 6. Этап 4. Отверстия | задания отверстий, `ПОС`/`ОВОС` (начало) | по диску ненадёжно (внутренние задания) |
| 7. Этап 5. Комплектация (экспертиза) | `Смета` (альбом для экспертизы), полные комплекты АР4/КЖ4/ВК3/ОВ3/ЭЛ3/СС3, ОПЗ, паспорт, энергопаспорт, письма заказчика | есть файлы `Смета` |
| 8. Этап 6. Экспертиза | раздел/папка верхнего уровня «Экспертиза» + наличие сметы; письма в экспертизу | папка верхнего уровня «эксперт…» (+ смета) |
| 9. Этап 7. На стройку / Выдача | папка «На стройку»/«Выдача», выдача IFC/чертежей | папка верхнего уровня «на стройку/выдача» |

Папки `Замечания` **внутри** раздела (напр. нормоконтроль в `АР`) — это НЕ стадия экспертизы; маркеры этапов берутся только с папок верхнего уровня.

## Что выводит сканер (кроме %)
- **Реальный этап** — максимальный достигнутый по артефактам (консервативно).
- **Дней без движения** — сегодня − дата последнего значимого файла (`.dwg/.pdf/.rvt/.ifc/.docx/.xlsx…`; мусор `.err/.dat/.slog/.log`, `~$…`, `acad*`, `editingperms` игнорируется).
- **Чей ход** — наш (проектирование) или заказчик/госорган (ИРД, экспертиза, письма, финансирование).
- **Аномалии / правило движения**:
  - ERP 0 %, а на диске артефакты позднего этапа → статус занижен;
  - ERP ~90 %/экспертиза, а на диске свежая работа раннего этапа → проверить статус/фазу (возможно, другая очередь в той же папке);
  - «На паузе» без явной даты возврата → авто-красный (нужна причина и дата);
  - «Ждём заказчика» давно без даты → задача ГИПу додолбить заказчика (поставить дату), а не пассивная пауза;
  - ≥90 % и стоит >30 дн → авто-эскалация;
  - «В работе», но >45 дн без новых файлов → реально ли движемся.

## Ограничения (честно)
- Одна папка проекта может содержать несколько очередей/блоков (напр. «Азамат → Атлетик», «АХБК 6 этажей», «Магнит 2 очередь»): сканер по корню смешивает фазы и может занизить/завысить этап — нужна привязка pm-проекта к подпапке конкретной очереди.
- Поле `folder` у pm-проектов пустое — сопоставление проект↔папка пока по номеру/имени; стоит завести `folder` в карточке.
- Этапы 2 и 6 по диску не видны — опора на ERP/оплаты/акты.
