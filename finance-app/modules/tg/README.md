# Модуль `tg` — Telegram-бот бюро

Уведомления MOST ERP в личный Telegram, ежедневный отчёт исполнителя, итог недели. Сайт ERP, раздел «Telegram» (`#/tgme`).
Без npm: Telegram Bot API через встроенный `fetch` (Node 24), приём — long polling (`getUpdates`) из процесса ERP; входящие вебхуки и порты не нужны.

## Сделано

- **Подключение бота** (только владелец): токен от @BotFather хранится в коллекции `tgConfig`; в ответах API и журнале действий — только `…последние 4 символа`. «Проверить» — `getMe`. Состояние опроса, очередь, ошибки. Ключу ИИ (`viaToken`) раздел бота закрыт целиком, менять что-либо в модуле ему нельзя (403).
- **Привязка людей** (все роли): «Подключить Telegram» → одноразовый код 6 цифр на 15 минут (`tgCodes`) → человек пишет боту `/start КОД` (или открывает ссылку `t.me/<бот>?start=КОД`, или просто присылает 6 цифр) → `chat_id` привязан к пользователю (`tgLinks`, один человек — один чат). Отвязка: в ERP (себя; владелец/партнёр — любого) и командой `/stop`. Группы и каналы игнорируются. Не больше 5 неверных кодов в час с одного чата.
- **Уведомления** (`tgOutbox` — очередь и журнал отправленного): тип включает владелец/партнёр в настройках модуля, человек выключает у себя (ERP или `/settings` в боте).
  - назначили исполнителем пункта; срок завтра / просрочен — сводкой в 9:00;
  - пункт вернули с замечанием / приняли; запрошен перенос срока (ГИП/ПМ проекта, иначе руководителям) и решение (автору запроса); напоминание руководителя;
  - блокеры старше 14 дней — по понедельникам 9:00 ГИП/ПМ своих проектов (владельцу/партнёру — все);
  - новые обращения WhatsApp (`crmInbox`, если модуль `crm` включён) — владельцу, партнёру, секретарю; опрос раз в 5 минут, событие `crm.inbox.new` тоже принимается;
  - владельцу — сводка в 9:00: просрочки, ждут решения (на проверке, переносы), блокеры, обращения. Цифры и ссылки, без денег.
- **Ежедневный отчёт исполнителя** (по умолчанию выключен): в 18:00 рабочего дня (праздники РК — по календарю pm) бот спрашивает «Что сделали сегодня?» с кнопками по открытым пунктам (≤ 8): «В работе» / «На проверку» / «Готово». Кнопка → `PUT /api/pm/items/<id>` **через `pm.handle` с правами самого человека** (чужой пункт — отказ pm). Текст ответа → запись «Заметка» в журнал проекта (`POST /api/pm/projects/<pid>/log`, автор — человек); при нескольких проектах бот спрашивает, куда записать.
- **Итог недели** — пятница 17:00 владельцу и партнёру: по проектам сделано, просрочено, переносы, возвраты, кто молчит (открытые пункты без отметок и записей за неделю).
- **Надёжность**: время — Asia/Almaty; тихие часы 21:00–8:00 (всё ждёт утра; ответы на команды и кнопки — сразу); окна расписания 9–12, 18–21, пт 17–21 — после простоя в другое время задача дня пропускается, а не шлётся ночью; отметки запусков в `tgState`, ключ дубля у каждого сообщения — после перезапуска повторов нет; ≤ 25 сообщений/сек, при 429 — пауза `retry_after`, при 403 (человек остановил бота) — отметка до следующего его сообщения; сеть/5xx — повтор, сообщения старше 72 ч не шлются; журнал отправленного чистится через 30 дней. Нет токена или модуль выключен — бот молчит. В режиме разработки (`DEV_USER`) бот ходит только в заглушку (`TG_API_BASE`).
- Назначения, возвраты и приёмка ловятся и без событий pm — сверкой пунктов раз в минуту (первый проход только запоминает); событие и сверка дают один ключ — без дублей.

## События (подписка)

`pm.item.done` (есть), `pm.item.reviewed`, `pm.shift.requested`, `pm.shift.decided`, `pm.remind`, `pm.item.assigned` (добавляет поток pm), `crm.inbox.new` (если появится). Пока события нет — подписка просто не срабатывает. Разбор данных терпимый: `{ item | itemId, project | pid, by | userId }`; reviewed — `accepted | result | decision`, `comment`; shift — `shift: { id, from, to, reason, by, approved | status }`; remind — `to | userIds`, `text`.

## Что нужно от директора

1. В Telegram: @BotFather → `/newbot` → имя (например «MOST ERP») и адрес бота → скопировать токен.
2. После выкладки: «Настройки → Модули» — включить `tg`; «Telegram» — вставить токен, «Проверить», «Подключить Telegram» себе, «Пробное сообщение себе».
3. Включить нужные типы (ежедневный отчёт — по желанию), проверить адрес ERP в ссылках (по умолчанию `http://192.168.50.51:3001`; для телефона вне офиса — адрес туннеля).
4. Сотрудники подключаются сами: раздел «Telegram» → «Подключить».

## Что осталось

- Правки ядра — `CORE-REQUESTS.md` (название модуля в «Настройках», порядок в меню, строка в ARCHITECTURE).

- Резервная копия базы содержит токен бота (как и всё остальное в базе) — хранить копии так же бережно.
