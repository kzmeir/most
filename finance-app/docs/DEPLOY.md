# Инструкция сисадмину — постоянный сервер MOST Финансы

Для пользователей — `README.md`. Здесь — пошагово: установка, обновление версии, откат, восстановление из
бэкапа, куда смотреть логи. Сопровождают систему директор и сисадмин (`docs/ARCHITECTURE.md`, «Решения
директора»); изменения в код — через Claude в этом репозитории.

Сервер — только **MostServer в офисе** (Docker), доступ снаружи — Cloudflare Tunnel. Облако не планируется;
если когда-нибудь понадобится — только в Казахстане (в базе персональные данные: ИИН, оклады), например PS Cloud
или Kazteleport.

Приложение — один процесс Node.js без npm-зависимостей. База — `data/db.sqlite` (встроенный `node:sqlite`,
нужен **Node 22.5+**, лучше **24** — в 22-й версии SQLite ещё под флагом). Старый `data/db.json` при первом
запуске новой версии переносится в SQLite сам, оригинал остаётся рядом как `db.json.migrated-<дата>`.

## Два сайта, один процесс

Один и тот же процесс `server.js` поднимает **два сайта** на двух портах (`docs/ARCHITECTURE.md`, «Два сайта»),
база и вход общие:

| Сайт | Порт (переменная) | Что отдаёт | Наружу? |
|---|---|---|---|
| **«Финансы»** | `PORT` (3000) | Финансовые разделы: операции, счета, ЗП, дашборд и т.д. Модули (ERP) не отдаёт. | **Нет.** Только офисная сеть/VPN. |
| **«MOST ERP»** | `ERP_PORT` (3001) | Только включённые модули (`modules/*`) + вход, `/api/me`, `/api/people`, чтение `/api/settings`. Финансовые API отдаёт 404 «Этот раздел — на сайте «Финансы»». | Да — через Cloudflare Tunnel. |

Смысл: в интернет светится только ERP (проекты, задачи), а операции/счета/ЗП физически недостижимы с сайта,
который слушает снаружи — даже если кто-то узнает пароль сотрудника без доступа к финансам, зайти в финансовые
API с ERP-адреса нельзя на уровне сервера, не только интерфейса.

## Установка (первый раз)

1. **Container Manager** (бывший Docker) — установите из Центра пакетов DSM, если ещё не установлен.
2. Скопируйте папку `MOST-Финансы` (эту, `finance-app`) на NAS **на локальный диск**, например
   `/docker/most-finance` (через File Station или `\\MostServer\docker\most-finance` по сети). Не на сетевую
   шару/SMB-подключение — SQLite в режиме WAL требует блокировок файловой системы, которых сетевые шары
   надёжно не дают (см. комментарий в `docker-compose.yml`).
3. Порты DSM **5000/5001 заняты** — не переопределяйте `PORT`/`ERP_PORT` на них. По умолчанию наружу (внутри
   офисной сети) торчат оба — 3000 («Финансы») и 3001 («MOST ERP», `docker-compose.yml` пробрасывает оба).
   На маршрутизаторе/файрволе разрешайте доступ к 3000 только из офиса; 3001 можно открывать шире (или вообще
   не пробрасывать порт наружу, а пускать интернет-доступ только через Cloudflare Tunnel — см. ниже).
4. Запуск:
   - Через интерфейс: Container Manager → **Проект** → **Создать** → путь к папке с `docker-compose.yml` → «Собрать».
   - Или по SSH на NAS: `cd /volume1/docker/most-finance && docker compose up -d`.
5. Откройте `http://MostServer:3000` (сайт «Финансы» — первый запуск настраивается только тут, на ERP-сайте
   `/api/setup` намеренно отдаёт 403), создайте аккаунт владельца. Дальше вход общий, `http://MostServer:3001`
   (MOST ERP) сразу пускает под тем же логином.
6. Автозапуск после перезагрузки NAS: обеспечен политикой `restart: unless-stopped` в `docker-compose.yml` —
   Docker сам поднимает контейнер, пока запущена служба Docker (она стартует с NAS автоматически).

**Не задавайте `DEV_USER`** ни в `docker-compose.yml`, ни в окружении контейнера — это отключает пароли
(режим только для разработки на своём компьютере, см. `docs/ARCHITECTURE.md`). Файл `docker-compose.yml` в
репозитории его не задаёт — так и должно оставаться.

## Обновление версии

1. Заберите новый код (новая папка/архив от разработки, или `git pull`, если папка — репозиторий).
2. Скопируйте файлы **поверх старых**, не трогая `data/` — база и бэкапы остаются на месте.
3. `docker compose up -d --force-recreate most-finance` (или в Container Manager: проект → «Собрать» заново).
4. Проверьте `docker compose ps` — статус `healthy` в течение ~30 сек (healthcheck дёргает `/api/status`).

## Откат на предыдущую версию

1. Остановите контейнер: `docker compose stop most-finance`.
2. Верните предыдущую копию папки с кодом поверх текущей (опять же не трогая `data/`) — если старой копии нет,
   возьмите файлы из истории Git (`git checkout <прошлый-коммит> -- .` в отдельной ветке) или из последнего
   присланного архива поставки.
3. `docker compose up -d`.
4. Если после отката база не читается (переносилась миграция вперёд, которой откат не знает) — восстановите
   `data/db.sqlite` из ближайшего бэкапа в `data/backups/` на момент до обновления (см. ниже).

## Логи

- `docker compose logs -f most-finance` — вывод сервера (запуск, ошибки запросов, туннель, если поднят рядом).
- `docker compose ps` — состояние контейнера и healthcheck (`/api/status`).
- Внутри приложения: раздел «Настройки → Журнал действий» (кто что менял) и, для владельца, экран
  «Сервис → Состояние системы» — версия, путь и размер базы, число и время последнего бэкапа, адрес туннеля.

## Доступ из интернета (Cloudflare Tunnel) — только сайт ERP

Блок `cloudflared` в `docker-compose.yml` закомментирован — включите при необходимости. **Публичный хост в
туннеле указывает на порт 3001 (ERP), не на 3000 (Финансы)** — так наружу физически не попадают финансовые API,
даже если кто-то ошибётся с правами в интерфейсе:

1. В [Cloudflare Zero Trust](https://one.dash.cloudflare.com/) → Networks → Tunnels → **Create a tunnel**,
   скопируйте токен.
2. Public Hostname туннеля → сервис `http://most-finance:3001` (имя контейнера + порт **ERP** в той же docker-сети).
3. Токен — в `.env` рядом с `docker-compose.yml`: `CLOUDFLARE_TUNNEL_TOKEN=...` (не коммитить, уже в `.gitignore`).
4. Раскомментируйте блок `cloudflared`, добавьте `TRUST_PROXY=1` в `environment:` контейнера `most-finance`
   (реальный IP посетителя тогда берётся из заголовка `CF-Connecting-IP`, который добавляет Cloudflare), `docker compose up -d`.

Для запуска с Windows-сервера вместо Docker (если Synology недоступен) — тот же результат даёт `start-internet.bat`
(`node tools/serve-internet.js` поднимает оба сайта одним процессом и ведёт туннель ТОЛЬКО на `ERP_PORT`,
перезапускает при сбое, путь к файлам — от `__dirname`, не зависит от текущей директории запуска), автозапуск —
`install-autostart.bat`.

**Проверка безопасности:** режим `DEV_USER` (вход без пароля) должен быть недоступен, если сервер поднят за
туннелем — ядро уже это проверяет (`server.js`, функция `devUser`: отказ при `TRUST_PROXY`, заголовках
`CF-Connecting-IP`/`X-Forwarded-For`, и только с адреса `127.0.0.1`). Тест — `tests/api_test.sh`, раздел
«DEV_USER»; прогоняйте после любых изменений в `server.js`.

## Бэкапы

- **Локально, автоматически** — уже работает: первая запись каждого дня делает `VACUUM INTO` копию
  `data/db.sqlite` в `data/backups/db-*.sqlite`, хранится 60 копий (`lib/store.js`). В Docker-варианте это
  внутри того же смонтированного тома — бэкапы переживают перезапуск контейнера.
- **В Google Drive, ежедневно** (нужен компьютер с Windows и установленным Google Drive для компьютера,
  папка `G:\Мой диск\...` — сам NAS для этого не подходит): скрипт `tools/backup-gdrive.ps1` берёт
  согласованный снимок `db.sqlite` (`VACUUM INTO`, без остановки сервера), убирает из копии таблицу сессий,
  добавляет прикреплённые файлы, кладёт zip. Вручную — `backup-gdrive.bat`. Чтобы шло само каждый день —
  один раз запустите `install-backup-task.bat` **от имени администратора**: регистрирует задачу Планировщика
  Windows на 03:00. Проверить: Планировщик заданий → «MOST Финансы — бэкап»; запустить сейчас —
  `schtasks /Run /TN "MOST Финансы - бэкап"`; удалить — `schtasks /Delete /TN "MOST Финансы - бэкап" /F`.
- **Восстановление** — через интерфейс: Настройки → Резервные копии → «Восстановить из файла» (владелец) —
  сама делает копию `before-restore` перед заменой. Из бэкапа вручную (сервер должен быть остановлен):
  скопируйте нужный `data/backups/db-*.sqlite` поверх `data/db.sqlite` (и `-wal`/`-shm` рядом, если есть —
  удалите их, чтобы не подхватились старые незакоммиченные страницы), запустите сервер.
- **Проверка восстановления** — сделайте один раз после разворачивания и держите процедуру в памяти: бэкап →
  испортить тестовую запись → восстановить → проверить, что данные вернулись. Автоматический тест на весь путь
  бэкап/восстановление через интерфейс — в `tests/api_test.sh` («backup/restore»); тест самого
  `backup-gdrive.ps1` (снимок, вычищение сессий, ротация копий) — `tests/backup_gdrive_test.ps1`, работает на
  тестовых путях, реальный `\\MostServer` и Google Drive не трогает.

## Учёт и уведомления — что сейчас НЕ делает система

- Главная учётная система — **1С**. ERP здесь — управленческий учёт и проекты, не дублирует бухгалтерский
  ввод; обмен с 1С — только выгрузки/загрузки CSV (Настройки → «Экспорт для 1С»), официальные документы (АВР,
  счета, ЭСФ) выписывает бухгалтер в 1С.
- **Уведомления** (Telegram/WhatsApp/почта) пока не реализованы — решение директора (`docs/ARCHITECTURE.md`,
  «Решения директора», 24.09.2026). Напоминания — внутри системы: счётчики и списки «просрочено», «ждёт вас».
