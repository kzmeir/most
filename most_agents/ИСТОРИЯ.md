# Агентная система MOST: история и контекст

Этот файл нужен, чтобы продолжить работу в локальной версии Claude Code (на офисном сервере рядом с NAS) без потери контекста. Его же можно положить в Obsidian.

## 1. С чего началось

Рилс Instagram: https://www.instagram.com/reel/DdlLVTjIEVl/
Автор: **artur_taam**, бюро **Rezeda** (https://rezeda-bureau.ru).
Кадры из рилса лежат в папке `reel/`.

Подпись к рилсу (дословно по смыслу): бюро строит работу вокруг ИИ («BIM 3.0»), берёт больше работы, чем раньше, не расширяя штат, но автор признаёт, что штат скоро всё равно придётся расширять.

Реакция: 1 747 лайков, 79 комментариев, 1 325 репостов, 1 257 сохранений. Сохранений почти столько же, сколько лайков: профессионалы сохраняют это как референс.

### Оценка

Сильные стороны:
* процесс разбит по стадиям проектирования, понятным архитектору;
* конфиденциальное идёт на локальную модель, тяжёлая логика в облако.

Слабые стороны:
* это витрина: ни одного реального результата (ТЗ, планировки, листа) в ролике нет;
* самое сложное не показано: рабочие разделы, нормы, экспертиза, ответственность ГИПа;
* 19 агентов дороги в поддержке, ошибки копятся на стыках, реальная экономия обычно в 3 или 4 узлах;
* подпись сама признаёт, что узким местом остались люди.

## 2. Решения директора (Meir, MOST Architects)

| Вопрос | Решение |
|---|---|
| Цель системы | **Рабочий инструмент**, визуальный граф вторичен |
| Первые агенты | **Аналитик задания, Участок и нормы РК, ТЭП и проверка, Архивариус** |
| BIM программа | **Revit** |
| Хранение файлов | **Локальный сервер / NAS** в офисе |

## 3. Согласованная архитектура

**Где работает:** офисный сервер или выделенный ПК рядом с NAS. Python сервис и веб интерфейс только во внутренней сети.

**Модели:**
* Claude (Opus 5.5) через Anthropic API для анализа: ТЗ, нормы, проверки. API данные по умолчанию не используются для обучения, но документы уходят в облако.
* Локальная модель только для эмбеддингов архива, чтобы полный архив MOST не покидал офис.
* Локальные модели уровня 14B для анализа русских нормативных текстов не использовать: слабо.

**Агенты:**

| Агент | Вход | Выход |
|---|---|---|
| Оркестратор | проект и задача | запуск агентов по цепочке, статусы |
| Аналитик задания | ТЗ, письма, протоколы (PDF, DOCX) | структурированное задание, противоречия, вопросы заказчику |
| Участок и нормы РК | АПЗ, данные участка, кадастр | ограничения со ссылками на пункты СП РК, СН РК, ПДП Алматы |
| ТЭП и проверка | выгрузка помещений и площадей из Revit (pyRevit) | таблица ТЭП, расхождения с ТЗ и нормами |
| Архивариус | папки проектов на NAS | поиск по прошлым проектам со ссылками на файлы |

**Интерфейс:** список проектов, граф агентов со статусами реальных запусков. Каждый результат подтверждает ГАП или ГИП, только потом он идёт дальше.

**Узкие места:**
1. База норм РК: машиночитаемой базы СП РК и СН РК нет, её нужно собрать из официальных PDF и обновлять. Без неё агент по нормам выдумывает пункты.
2. Revit: нужна надстройка pyRevit для выгрузки помещений и площадей в JSON, проверяется только на машине с Revit.

## 4. Порядок работ

1. Каркас сервиса и Архивариус (индексация NAS, поиск).
2. Аналитик задания.
3. Участок и нормы РК вместе с базой норм.
4. ТЭП и проверка вместе с надстройкой Revit.

## 5. Что нужно подготовить

* Версия Revit, характеристики сервера (ОС, RAM, GPU).
* Один завершённый проект для тестов: ТЗ, АПЗ, таблица ТЭП.
* Ключ Anthropic API в переменной окружения `ANTHROPIC_API_KEY` на сервере. В чат не отправлять.
* Путь к папке проектов на NAS.

Открыть Claude Code на офисном сервере в папке с этим файлом и написать:
